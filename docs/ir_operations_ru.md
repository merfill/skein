# Skein — операции над IR: справочник и матрица тестов

> Английский оригинал — `docs/ir_operations.md`.

Связанные: `docs/ir_semantics_ru.md` (формальная семантика — этот документ есть
операционный справочник и контракт покрытия, а не вторая формализация),
`docs/projection_ru.md`, `docs/tools_ru.md`, `docs/ir_ru.md`, `docs/walkthrough_ru.md`,
`docs/testing_ru.md`.

Статус: **Реализовано.** §1–§4 специфицируют модель и каждую операцию; §5 —
матрица покрытия (заполнена). Идентификатор **стабилен**: у пункта могут появиться
тесты, но его смысл не меняется.

> **Редуцированная модель цели** (`docs/plans/goal_reduction_plan_ru.md`). Цель — это
> `what` + контейнер плана, засеянный первой командой. Закрытие
> динамическое: `stop` доксы закрывает цель; нет критерия, нет гейта по exit code, нет
> `done_when`/`step`/`revises` и нет `state` (`exitCode` — обычный вывод).

---

## 0. Как читать этот документ

Каждая операция описана как:

- **Pre** — когда допустима (допустимые ходы/предусловие логоса).
- **Effects** — какие события журнала и какое изменение дерева она эмитит.
- **Derived** — какие факты меняются в результате.
- **Refuses** — причины отказа (`classify`), каталог в §3.
- **Projection** — как результат виден в следующем контексте (§ проекция).
- **ID** — стабильный идентификатор; тест ссылается на него как на токен `ID` в заголовке.

Семейства ID: `OP-CG` create_goal, `OP-AP-READ|GREP|LIST|EDIT|WRITE|RUN|FETCH|PATCH`
инструменты `apply`, `OP-AP-PLACE` как `apply` ложится в дерево, `OP-ST` stop,
`OP-DC` decline, `OP-RC`/`OP-SR` recall/search, `TR` обход/контейнеры, `DER` производные
факты/предикаты, `REF` отказы (каталог), `PRJ` проекция (ссылки).

## 1. Модель

### 1.1 Рабочие узлы (`src/ir/types.ts`)

| Kind | Payload | Роль |
|---|---|---|
| `request` | `{text}` | сырая мотивация; корень; интерпретируется один раз (`goal`) или отклоняется (`unactionable`); завершается, когда его цель остановлена |
| `goal` | `{what}` | интерпретация запроса или подцель |
| `plan` | — | упорядоченный контейнер пунктов цели (`items`); ПОСЛЕДНИЙ пункт — текущий |
| `item` | — | упорядоченный контейнер альтернатив пункта (`alts`: действия или подцели); ПОСЛЕДНЯЯ — текущая |
| `action` | `{command, ...}` | один прогон инструмента; альтернатива пункта |
| `observation` | `{ref?, version?, command?, exitCode?, output/error/...}` | тело результата инструмента; `exitCode` — обычный вывод, не оракул закрытия |
| `stop` | `{why?}` | закрывает цель в фокусе; связь `stop` от цели |
| `unactionable` | `{why?}` | намерение запроса не действенно; докса отказывается формулировать цель (связь `unactionable`) |
| `constraint` | `{forbid: string[]}` | инвариант; сеется при старте прогона |
| `file` (artifact) | — | упомянутый файл; порождается `mutates` |

### 1.2 Связи (`src/ir/types.ts`)

| Связь | From → To | Смысл |
|---|---|---|
| `goal` | request → goal | единственная интерпретация запроса (фиксирована) |
| `unactionable` | request → unactionable | докса отказалась формулировать цель для запроса |
| `plan` | goal → plan | контейнер плана цели |
| `stop` | goal → stop | цель закрыта доксой |
| `items` | plan → item | упорядоченное членство (порядок = последовательность; ПОСЛЕДНИЙ пункт — текущий) |
| `alts` | item → action/goal | упорядоченные альтернативы пункта (ПОСЛЕДНЯЯ — текущая) |
| `result` | action → observation | тело результата действия |
| `mutates` | action → file | действие изменило файл |

### 1.3 События (`src/ir/events.ts`)

`add_node`, `add_edge`, `descend`, `return`, `mutate`, `record_rejection`. `fold`
применяет их по порядку; состояние (`children`, `branch`, `focusOf`, версии) —
**производное**, никогда не хранится. Нет `record_check` и нет `set_status`: смена
состояния — это новое событие-узел (`observation`/`stop`). Результат прогона — обычная
`observation`; её `exitCode` — вывод, не вердикт.

### 1.4 Контейнеры и обход

- **branch** — стек целей от корня-запроса до фокуса; `descend` кладёт, `return` снимает (`TR-1`).
- **focus** — `branch[last]`, иначе корень (`TR-1`).
- **plan** — цель связи `plan`; **пункты** — рёбра `items` в порядке вставки;
  **последний** пункт — текущий.
- **alternatives** — дети пункта (`alts`); **текущая** альтернатива — последний
  ребёнок (связи `chosen` нет).
- **frontier** — допустимые ходы в фокусе, вычисляются **один раз** и разделяются
  проекцией и `classify` (`TR-8`). Доксе выдаётся всё **плечо** (соседи уровня) с
  **курсором** только на текущем узле; движок не диктует единственный следующий ход.

## 2. Операции

### 2.1 `create_goal` (`OP-CG`)

| Случай | Pre | Effects | Derived | Refuses | ID |
|---|---|---|---|---|---|
| у запроса (интерпретация) | фокус — `request` ещё без цели | добавить `goal` (`what`); связь `goal` request → goal; добавить `plan` с одним `item`, чья единственная альтернатива — `command`; логос сразу исполняет `command`; `descend` | интерпретация фиксирована; первый пункт цели исполнен | `empty_what`, `empty_command`, `interpreted` | `OP-CG-1` |
| декомпозиция открытой цели | фокус — `goal` с текущим пунктом | добавить `goal`; добавить его новейшей альтернативой текущего пункта (`alts`); добавить его план/пункт с первой командой (исполняется сразу); `descend` | подцель — новейшая альтернатива пункта | как выше; `no_current_item` | `OP-CG-2` |
| план + первая команда | любой из случаев, есть `command` | добавить ровно один пункт с единственной альтернативой `command` под новый `plan` | пункт текущий; команда исполнена | `empty_command` | `OP-CG-3` |
| один пункт плана | сев материализуется ровно одним пунктом | план содержит один пункт (одну команду) | последующие ходы добавляются по исходу (см. `OP-AP-PLACE`) | — | `OP-CG-4` |

- **Projection** (`PRJ-CG`): лента получает `assistant`-сообщение о цели; цель несёт план и
  альтернативы как историю.
- **Notes.** `why` — гипотеза, показывается, чтобы провалившаяся попытка не повторялась.
  Декомпозиция открытой цели требует текущего пункта; без него ход отклоняется
  (`no_current_item`). Первую команду несёт `command` — это не особый `step`, и логос исполняет
  её сразу.

### 2.2 `apply` (`OP-AP`)

Диспетчер одного инструмента в фокусе (`src/tools/index.ts`, `OP-AP-*`).

**Как `apply` ложится в план** — движок размещает приходящую команду по исходу текущего
(первого невыполненного) пункта (`docs/ir_semantics_ru.md` §2.7): если пункт уже выполнен (его
текущая альтернатива успешна), команда становится новым пунктом плана (`OP-AP-PLACE-2`);
иначе — новой альтернативой этого пункта (`OP-AP-PLACE-1`). Подцель (`create_goal` на
открытой цели) всегда становится новой альтернативой. Движок никогда не входит в действие.

#### 2.2.1 `read` (`OP-AP-READ`)

| Случай | Pre | Effects | ID |
|---|---|---|---|
| новое окно | путь существует; мир не менялся с прошлого идентичного чтения | добавить `action`; добавить `observation` (`result`); записать наблюдённую версию | `OP-AP-READ-1` |
| продолжение окна | другие `start/end` | новое действие/наблюдение | `OP-AP-READ-2` |
| отсутствующий файл | — | действие + fail-observation | `OP-AP-READ-3` |
| повтор | идентичное окно, мир не менялся | отказ `repeated_action` | `OP-AP-READ-4` |
| путь вне workspace | — | действие + fail-observation (записанный отказ, без краха) | `OP-AP-READ-5` |
| трэш чтения | несколько разных окон одного файла | каждое разное окно — новое действие/наблюдение (лимита на файл нет); идентичное окно — `OP-AP-READ-4` | `OP-AP-READ-6` |
| большое окно | запрошенное окно больше байтовой границы | наблюдение показывает окно целиком (середина никогда не отбрасывается); обрезается лишь отдельная сверхдлинная строка, полное окно — за `outputRef`, достаётся `recall` | `OP-AP-READ-7` |
| бюджет чтения | файл длиннее байтового бюджета | окно режется по целым строкам до `READ_LIMIT`; трейлер `continue from N` указывает следующее окно | `OP-AP-READ-8` |

#### 2.2.2 `grep` (`OP-AP-GREP`)

| Случай | Pre | Effects | ID |
|---|---|---|---|
| поиск по scope | `path`/`include`/`exclude` валидны | действие + наблюдение (JSON-окна) | `OP-AP-GREP-1` |
| пагинация | `from`/`count` | новое действие/наблюдение; повтор того же паттерна с новым `from` — новое | `OP-AP-GREP-2` |
| нет попаданий / плохой scope | — | пустой результат / fail-observation | `OP-AP-GREP-3` |
| повтор | идентичные scope+паттерн, мир не менялся | отказ `repeated_action` | `OP-AP-GREP-4` |
| байтовый бюджет | окно совпадений превысило бы байтовую границу | целые хвостовые результаты отбрасываются, чтобы JSON остался в границе; `returned` ниже окна count и `next` задан; отдельный огромный результат обрезается построчно | `OP-AP-GREP-5` |
| границы count | `count` отсутствует или слишком велик | окно не больше `GREP_COUNT_DEFAULT` (50), но никогда больше `MAX_GREP_MATCHES` (100) | `OP-AP-GREP-6` |

#### 2.2.3 `list` (`OP-AP-LIST`)

| Случай | Pre | Effects | ID |
|---|---|---|---|
| список по scope | — | действие + наблюдение (пути как JSON) | `OP-AP-LIST-1` |
| пагинация / пусто | `from`/`limit` | новое действие/наблюдение | `OP-AP-LIST-2` |
| байтовый бюджет | страница превысила бы байтовую границу | целые хвостовые файлы отбрасываются, чтобы JSON остался в границе; `returned` ниже страницы и `next` задан | `OP-AP-LIST-3` |

#### 2.2.5 `run` (`OP-AP-RUN`)

`run` — одна простая **foreground**-команда. Нет критерия, нет `target` и нет механики
фоновых jobs.

| Случай | Pre | Effects | Derived | Refuses | ID |
|---|---|---|---|---|---|
| команда | есть `command` | действие + `observation` (`command` + `exitCode`); `mutate` на каждый изменённый файл | версии; старые чтения устаревают | `repeated_action` | `OP-AP-RUN-1` |
| большой вывод | поток больше байтовой границы | наблюдение держит **хвост** inline (ошибка и exit в конце) с пометкой об усечении; полный поток — за `outputRef`/`errorRef`, достаётся `recall` | — | — | `OP-AP-RUN-2` |

- **Projection** (`PRJ-AP`): узел результата — `lastResult`; stdout (`output`) и
  stderr (`error`) раздельны; крах добавляет `signal`/`core`/`backtrace`; запись в
  `calls` несёт `id` для последующего `recall`/`search`.

| Случай | Pre | Effects | Derived | Refuses | ID |
|---|---|---|---|---|---|
| создание | `path` не существует | добавить `action` (`path`/`content`); `mutate`; версия файла задана | — | — | `OP-AP-WRITE-1` |
| перезапись | файл прочитан и не менялся с того чтения; не запрещён | добавить `action`; `mutate`; версия меняется | зависимые факты устаревают | `stale_base`, `constraint_violation:<pattern>` | `OP-AP-WRITE-2` |
| запрещённый путь | запрет constraint | — | — | `constraint_violation:<pattern>` | `OP-AP-WRITE-3` |
| устаревшая база | файл изменился после последнего чтения | — | — | `stale_base` | `OP-AP-WRITE-4` |
| непрочитанный файл | файл существует, но не читался | — | — | fail-observation (`read it first`) | `OP-AP-WRITE-5` |
| путь вне workspace | — | fail-observation (записанный отказ, без краха) | — | — | `OP-AP-WRITE-6` |

- **Projection** (`PRJ-AP`): исполненный узел `action` с ребром `mutates` и событием

#### 2.2.7 `fetch` (`OP-AP-FETCH`)

Получает внешние референсные данные (upstream/опубликованную/соседнюю копию) в
workspace, чтобы их можно было читать и диффить (B9, `docs/system_prompt_ru.md`).

| Случай | Pre | Effects | Derived | Refuses | ID |
|---|---|---|---|---|---|
| fetch | URL достижим; цель не существует; не запрещена | действие; записать файл; `mutate` + `mutates`; наблюдение (`url`/`path`/`bytes`) | версия файла задана; старые чтения устаревают | — | `OP-AP-FETCH-1` |
| сбой загрузки | не-2xx / таймаут | fail-observation | — | — (fail) | `OP-AP-FETCH-2` |
| цель существует / путь вне workspace | — | fail-observation (`choose another path` / записанный отказ) | — | — | `OP-AP-FETCH-3` |
| запрещённый явный путь | запрет constraint | — | — | `constraint_violation:<pattern>` | `REF-FETCH-CONSTRAINT` |

Цель по умолчанию принадлежит движку (`refPathFor`, `.skein/ref/<hash>-<slug>`), поэтому
проверяется по constraint только явный `path`.

#### 2.2.8 `apply_patch` (`OP-AP-PATCH`)

Применяет unified diff в корне workspace (`patch -p<strip>`, по умолчанию 1), например
upstream-изменение, полученное через `fetch`.

| Случай | Pre | Effects | Derived | Refuses | ID |
|---|---|---|---|---|---|
| примененимо | патч применяется чисто | действие; `mutate` на каждый изменённый файл (`patch -p<strip>`) | изменённые версии; старые чтения устаревают | — | `OP-AP-PATCH-1` |
| не применяется | конфликтующий/уже применённый hunk | fail-observation | — | — (fail) | `OP-AP-PATCH-2` |
| запрещённая цель | constraint запрещает путь `---`/`+++` | — | — | `constraint_violation:<pattern>` | `REF-PATCH-CONSTRAINT` |

### 2.3 `decline` (`OP-DC`)

Докса предполагает, что намерение запроса **не действенно** (болтовня, нет задачи) и
отказывается формулировать цель — вместо выдумывания цели. Доступно только пока у
запроса ещё нет интерпретации; записывает узел `unactionable` под запросом (связь
`unactionable`) и завершает прогон (`docs/plans/archive/request_goal_plan.md`).

| Случай | Pre | Effects | Derived | Refuses | ID |
|---|---|---|---|---|---|
| отклонить запрос | фокус — запрос без интерпретации и без узла `unactionable` | добавить узел `unactionable` и связь `unactionable` от запроса; прогон завершается | запрос терминален (`request_unactionable`) | — | `OP-DC-1` |
| не у запроса | фокус — цель | — | — | `not_request` | `REF-DC-NOTREQ` |
| уже интерпретирован | у запроса уже есть интерпретация | — | — | `interpreted` | `REF-DC-ADDR` |

- **Projection** (`PRJ-DC`): опция `decline` предлагается у свежего запроса рядом с
  `create_goal`.

### 2.4 `stop` (`OP-ST`)

Терминальный ход доксы и **единственное закрытие**. На **цели** он завершает кадр
(движок возвращается к родителю на следующей проекции и продолжает); на **запросе**
завершает прогон. Критерия и проверки нет: докса решает в процессе.

| Случай | Pre | Effects | Derived | Refuses | ID |
|---|---|---|---|---|---|
| завершить открытую цель | фокус — цель | добавить узел `stop` и связь `stop` от цели | цель закрыта; движок возвращается | — | `OP-ST-1` |
| закрытие записано на цели | цель | узел `stop` подвешен к цели (не пункт плана); причина — в его `why` | закрытие и его причина лежат на цели | — | `OP-ST-2` |
| запрос завершается | у цели запроса есть связь `stop` | прогон завершается | stopReason `request_addressed` | — | `OP-ST-3` |
| не у цели | фокус — запрос | — | — | `not_addressed` | `REF-ST-STATE` |

- **Projection** (`PRJ-STOP`): лента показывает сообщение о закрытии `stopped: <why>`;
  внутренности закрытой цели уходят из ленты.
- Цель закрывается только через `stop` (связь `stop`). На запросе `stop` нет; запрос
  завершается, когда его цель остановлена.

### 2.5 `recall` и `search` (`OP-RC`, `OP-SR`)

Два хода читают сохранённый результат по id (механизм «индекса», docs/ir_semantics.md §4.5):
`recall` открывает тело (при желании окно строк), `search` ищет в нём паттерн. Ни один не
создаёт узел — результат приходит транзиентной парой `assistant`+`tool` на следующий ход
(docs/ir_semantics.md §7). Это отдельные инструменты, чтобы докса не путала чтение
файла/результата (`read`) с поиском (`grep` / `search`).

`recall { id, start?, end? }` (`OP-RC`):

| Случай | Pre | Effects | ID |
|---|---|---|---|
| по id | id адресует сохранённое тело (наблюдение или тело inline/`Ref`) | узла нет; окно тела возвращено; курсор `continue from N`, если тело длиннее | `OP-RC-1` |
| окно | `start`/`end` | строчное окно; продолжается новым `recall` | `OP-RC-2` |
| большое тело | тело больше байтового бюджета | окно ужимается по целым строкам (`QUERY_BODY_LIMIT`, валидный JSON, без обрезки посреди строки); поток ошибок, если есть, — ограниченный inline-хвост | `OP-RC-3` |
| нет тела | id — действие/цель/и т.п. | `(nothing to recall: <id> has no stored body)` | `OP-RC-4` |
| неизвестный id | — | `(nothing to recall: <id> is not a node)` | `OP-RC-5` |
| транзиент | — | узла нет; добавляется в ленту транзиентной парой | `OP-RC-6` |

`search { id, pattern, before?, after? }` (`OP-SR`):

| Случай | Pre | Effects | ID |
|---|---|---|---|
| по паттерну | id адресует сохранённое тело; `pattern` — регулярное выражение | узла нет; окна совпавших строк по stdout **и** stderr как JSON, с контекстом | `OP-SR-1` |
| stderr | у тела есть поток ошибок | совпадения в stderr несут `stream: "stderr"` | `OP-SR-2` |
| широкий паттерн | совпадений больше, чем вмещает окно | целые хвостовые результаты отбрасываются; `note` говорит `showing N of M; narrow the pattern` — никакого висящего `next` (у `search` нет пагинации) | `OP-SR-3` |
| нет совпадений | — | пустой `results` | `OP-SR-4` |
| невалидный паттерн | `pattern` — не регулярное выражение | `{ …, error: "invalid pattern" }` | `OP-SR-5` |
| нет тела | у id нет сохранённого тела | `(nothing to search: <id> has no stored body)` | `OP-SR-6` |
| контекст | `before`/`after` | строки контекста на совпадение (по умолчанию 3/3) | `OP-SR-7` |

- **Projection** (`PRJ-RC`): тело из recall/search входит в ленту транзиентной парой
  `assistant`+`tool` на следующий ход; запросы состояния не закрепляются.
- **Projection** (`PRJ-REF`): отклонённый структурный ход (узла нет) входит в ленту
  транзиентным `tool`-сообщением (`rejected <ход>: <причина>`) на следующий ход.

### 2.6 Обход и контейнеры (`TR`)

| Случай | Правило | ID |
|---|---|---|
| фокус | фокус — `branch[last]`, иначе корень | `TR-1` |
| descend | `focusEvents` спускается в цель запроса (`goal`) или в подцель-альтернативу текущего пункта (`alts`) | `TR-2` |
| return | завершённый верх снимается; `return` допустим | `TR-3` |
| обрезка под завершённым предком | если любой предок (кроме корня) завершён, ветка обрезается — не только когда завершается верх | `TR-4` |
| выбор контейнера | план цели — `plan` (`plan`); интерпретация запроса — связь `goal`; альтернативы пункта — `alts` | `TR-5` |
| порядок пунктов и курсор | пункты идут по порядку `items` (ПОСЛЕДНИЙ текущий); курсор — первый не `itemFulfilled`; пункт выполнен, когда его текущая альтернатива — успешное действие или закрытая цель | `TR-6` |
| размещение | приходящая команда становится новым пунктом, когда текущий пункт выполнен, иначе новой альтернативой его (`OP-AP-PLACE`) | `TR-7` |
| frontier | `applicable` вычисляет create_goal/apply/stop/decline из тех же фактов, что и гейты; докса выбирает среди них | `TR-8` |
| альтернативы пункта | альтернативы пункта (его история) рендерятся в ленте с пометкой | `TR-9` |

### 2.7 Производные факты (`DER`)

Состояние всегда выводится из инцидентных событий, никогда не хранится.

| Предикат | Правило | ID |
|---|---|---|
| цель закрыта | у цели есть связь `stop` к узлу `stop` | `DER-GOAL-1` |
| действие `executed` | у него есть связь `result` или `mutates` | `DER-ACT-1` |
| witness прогона | наблюдение прогона несёт `witness` (основа устаревания) | `DER-STALE-1` |

## 3. Отказы и неисполнение команд (`REF`)

Гейт `classify` (`src/loop/classify.ts`) отклоняет только **структурный** ход: он эмитит
`record_rejection` и **обязан изменить проекцию** (инвариант). **Команду** обрабатывает
движок (`src/tools/index.ts`): её неисполнение записывается как `action` + `observation` с
причиной, а не отказом без узла.

**Структурные отказы (`record_rejection`):**

| Причина (токен) | Триггер | Оператор | ID |
|---|---|---|---|
| `empty_what` / `empty_command` | некорректный `create_goal` | `create_goal` | `REF-CG-EMPTY` |
| `no_current_goal` | фокуса нет | create_goal | `REF-NO-FOCUS` |
| `interpreted` | второй `create_goal` у запроса, уже имеющего цель | create_goal | `REF-INTERPRETED` |
| `not_addressed` | `stop`, когда фокус — не цель (запрос) | stop | `REF-ST-STATE` |
| `not_request` | `decline` вне фокуса-запроса | decline | `REF-DC-NOTREQ` |
| `interpreted` | `decline` у запроса, уже имеющего цель | decline | `REF-DC-ADDR` |

**Неисполнение команды (`action` + `observation` с причиной):**

| Причина | Триггер | Оператор | ID |
|---|---|---|---|
| `repeated_action` | идентичные read/grep/run при неизменном мире | read/grep/run | `REF-REPEAT` |
| `repeated_action` | голый recall по телу, уже видимому (recall с окном — новое содержание) | recall | `REF-RECALL-REPEAT` |
| run без команды | пустой `run` | run | `REF-RUN-EMPTY` |
| `stale_base` | edit по файлу, изменившемуся после чтения | edit | `REF-EDIT-STALE` |
| `constraint_violation:<pattern>` | edit запрещённого пути | edit | `REF-EDIT-CONSTRAINT` |
| `stale_base` | write поверх файла, изменившегося после чтения | write | `REF-WRITE-STALE` |
| `constraint_violation:<pattern>` | write запрещённого пути | write | `REF-WRITE-CONSTRAINT` |

**Провалы инструментов** (fail-observation): отсутствующий файл (`read`), плохой scope
(`grep`/`list`), `find` отсутствует (`edit`), ненулевой код/таймаут/сигнал (`run`).

## 4. Инварианты

- цель закрывается только через `stop` (связь `stop` на цели); прогона критерия и гейта по
  exit code нет.
- запрос завершается, когда его цель остановлена (на запросе `stop` нет); запрос
  интерпретируется один раз (`goal`) или отклоняется (`unactionable`).
- прогон — обычная `observation`; её `exitCode` — вывод, не вердикт.
- неисполненная команда оставляет `action` + `observation` с причиной (никогда не отказ без
  узла); недопустимый структурный ход отклоняется без узла.
- `stale`-факт никогда не показывается как активный.
- `project` детерминирован: те же события → тот же `Context`.
- структурные связи (`goal`/`unactionable`/`plan`/`stop`/`items`/`alts`) образуют DAG.
- каждая не-корневая цель привязана связью `goal` или `alts`.
- отказ/провал меняет проекцию.
- завершённая цель (и её потомки) не остаётся фокусом (`TR-4`); внутренности закрытой цели
  уходят из ленты.
- секреты живут только в `.env`; малые результаты могут инлайниться, секреты — никогда.

Первые четыре реализуют хелперы: `tests/invariants.ts`.

   (и, если новый, токен отказа в §3).
