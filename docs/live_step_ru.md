# Skein — реальный движок, ход за ходом

> Рабочий документ. Как `bench/live-step.ts` гоняет **реальный** движок на задаче по одному
> ходу, а контейнер задачи исполняет инструменты. Дополнение к `docs/state_testing_ru.md`
> (лента, контейнер, шаговый харнесс) и `docs/testing_ru.md`.

## 1. Зачем

Это **единственный** пошаговый раннер. Прежний replay-харнесс (`bench/step.ts`, удалён)
переигрывал записанную последовательность действий и вызывал `propose` напрямую, обходя
`executeNode`: в журнале не было `payload.reasoning`, а переходы/отказы/staleness были
харнесса. `bench/live-step.ts` сохраняет реальный цикл: `runAgent` и проекция работают на хосте,
а файловые инструменты, `bash`, фоновые jobs и checkpoint — в контейнере задачи
(rootless Docker; host-копии `/app` нет), процесс живёт между ходами.

## 2. Запуск

```sh
npx tsx bench/live-step.ts fix-ocaml-gc --net off
npx tsx bench/live-step.ts fix-ocaml-gc --net off --auto --turn 20
```

Опции:

| флаг | смысл |
|---|---|
| `--net on\|off` | сеть для хостового `fetch` (off — через allowlist-прокси API); `run`/jobs — в контейнере; контейнер задачи всегда `--network none` |
| `--dir <path>` | каталог трассы (по умолчанию `bench/runs/sandbox-tasks/<ts>-<id>-live-step`) |
| `--signal <path>` | файл-сигнал продолжения (по умолчанию `<dir>/continue`) |
| `--auto` | не ждать между ходами |
| `--turn N` | остановиться после абсолютного хода `N` |

Без `--auto` процесс печатает ход и ждёт; `touch <dir>/continue` — следующий ход,
`touch <dir>/quit` — остановка.

## 3. Как исполняется ход

1. `openTaskWorkspace(task, { network })` (`tests/sandbox/harness.ts`) для Docker идёт
   rootless-путём: контейнер стартует из образа, `/app` не копируется на хост, checkpoint живёт
   в `/tmp/.skein`; выполняется `setup` и снимается начальный checkpoint. Это тот же helper, что
   использует полный прогон (`runTask`).
2. Первый вызов — обычный `runAgent` с `maxTurns: 1`; он засевает запрос и session probe.
3. Каждый следующий вызов получает предыдущие `events` как `seed` и `startTurn = result.turns`,
   а `maxTurns: startTurn + 1`. `executeNode` по-прежнему исполняет настоящий ход: классификация,
   инструменты в контейнере, запись reasoning в журнал, переходы/откат. `max_turns` в конце
   вызова — только граница паузы, а не вердикт прогона.
4. Цикл заканчивается собственным закрытием движка (`done` с причиной, отличной от
   `max_turns`), либо по `--turn`/`quit`.

Процесс долгоживущий, поэтому `Workspace`, контейнер и дерево одни и те же между ходами —
ничего не переигрывается.

## 4. Что показывает ход

- состояние: `situation/island`, токены модели (`in/out/reasoning`), cache, стоимость, размер
  контекста;
- вызовы доксы (`call <tool> <args>`);
- наблюдения только что исполненного хода (`exit`, хвост вывода);
- дифф дерева от начального post-setup состояния по checkpoint-хранилищу
  (`diff -rq trees/0 trees/N`);
- путь к ленте.

Файлы в `--dir`:

| файл | содержимое |
|---|---|
| `contexts/tNNN.txt` | ровно сообщения, отправленные модели |
| `contexts.ndjson` | входы проекции по ходам (situation, island, history) |
| `reasoning.ndjson` | скрытый reasoning провайдера по ходам |
| `turns.ndjson` | вызовы, usage, стоимость, stop reason |
| `journal.ndjson` | полный журнал событий после каждого хода |

## 5. Ограничения

- Драйвер загружает модули промта один раз. Правка текста промта действует только после
  перезапуска; для свежего мира задачу надо начинать заново (старый журнал остаётся в трассе).
- Искусственная граница «один ход» даёт `stopReason=max_turns` на обычном ходу; драйвер её
  игнорирует и продолжает с возвращённого журнала.
- Правила доказательства те же, что у любого живого прогона: `temp=0.1` шумит, поэтому `K≥3`
  и один фактор за раз.
