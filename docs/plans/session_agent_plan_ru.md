# Tier 4b — SessionAgent: статусы внимания, обзор L0/L1, операции сессии

> Английское зеркало — `docs/plans/session_agent_plan.md`.
>
> Обновление (2026-10-31): `read`/`grep`/`list`/`probe` убраны из SessionAgent; работа с материалом перенесена в general-unit (`docs/plans/general_unit_plan_ru.md`). Остальное — исторический срез 4b.
>
> Статус: **первый срез реализован** (статусы, L0/L1, session-unit + `SessionAgent`,
> `respond`/`start`, инструменты `read`/`unit`/`state`/`turns`/`body`/`search`; `attempt` отложен).
> Не входит: драйвер нескольких utterance, reading island, пины, `revise`, прерывание
> пользователем, live-прогоны.
>
> **Словарь операций пересмотрен:** доступны только `respond` и `start`; `resume`/`cancel`/
> `redirect` из модели убраны (`resume` — будущая стратегия, `cancel` — не операция). Ниже
> сохранены исторические фрагменты с прежним словарём.

## 1. Цель

Сделать сессию полноценной единицей работы: движок может держать несколько task-unit'ов в одной
сессии, детерминированно строить по ним обзор и интерпретировать свободную реплику как
**операцию сессии**, которую предлагает `SessionAgent`, а логос проверяет и применяет.

Семантика дерева задачи не меняется: журнал unit'а только растёт, состояние закрывается только
`stop` доксы, проекция детерминирована. Статусы сессии — это внимание, а не истина; session-unit
никогда не пишет `move`/`stop`/`plan` в дерево задачи.

## 2. Зафиксированные входы

- `docs/session_concepts_ru.md` §2 (unit'ы, сессия, стек, pending, два статуса), §4
  (SessionAgent и его операции), §5 (обзор L0–L4), §7 (инварианты), §10 (минимальный шаг:
  L0/L1 + `respond`/`start`; остальные операции отложены).
- `docs/controllability_ru.md` §1.4/§2: agent-unit — тот же механизм, что и RequestObserver:
  свой журнал, другой корень и словарь, read-only-инструменты обзора, предложения проверяет
  логос.
- As-built-каркас 4a: `src/session/types.ts`, `session.ts`, `observer.ts`; посеянный обзор —
  событие журнала с origin `engine`, а не временный рендер.
- Инварианты: журналы только дописываются; `project` детерминирован; закрытие — только через
  `stop`; никаких вердиктов и хранимых статусов истины; `abandoned` не закрывает состояние.

## 3. Объём

**Входит:**

- статусы внимания в журнале сессии: `suspend`, `resume`, `abandon`; `completed` — производный;
- детерминированный иерархический обзор **L0 (сессия)** и **L1 (unit)** с явным усечением
  (`k more` + курсор);
- session-unit и `SessionAgent`: ограниченный цикл со своим промптом, реплика как корень,
  read-only-инструменты обзора, одна операция за прогон;
- операции `respond` и `start`: логос проверяет предусловия и применяет их как события сессии;
  журналы задач не трогаются;
- офлайн-тесты и обновление as-built-доков после реализации.

**Не входит:**

- драйвер нескольких utterance (реплика → операция → запуск/возобновление task-unit);
- `revise`, `query`, пины и reading island;
- прерывание пользователем, live/bench-прогоны без явного go-ahead;
- similarity/RAG и второй движок: session-unit — тот же механизм, что в 4a.

## 4. Целевая архитектура

### 4.1. Статусы внимания

`src/session/types.ts` добавляет в журнал сессии:

```ts
| { type: "suspend"; unitId: string; turn: number }
| { type: "resume"; unitId: string; turn: number }
| { type: "abandon"; unitId: string; turn: number }
| { type: "operation"; unitId: string; turn: number; operation: SessionOperation }
```

`SessionOperation` — закрытый union:

```ts
| { kind: "respond"; text: string }
| { kind: "start"; text: string }
```

`src/session/session.ts` получает `suspendUnit`, `resumeUnit`, `abandonUnit`, `recordOperation`
и `attentionOf(session, unitId)`. Статус **выводится из журнала**, а не хранится полем:

- `abandoned` — последнее событие внимания для unit'а — `abandon`;
- `completed` — unit терминален по своему журналу (task, чей запрос завершён: терминальное
  состояние остановлено или запрос `unactionable`; session-unit, чья операция записана) и при этом
  не `abandoned`;
- `active` — unit в фокусе (вершина стека);
- иначе `suspended`.

`abandon` и `suspend` пишут только журнал сессии; никакого события задачи, `stop` или изменения
состояния. Факт открыт/закрыт остаётся фактом журнала unit'а.

### 4.2. Обзор L0/L1

`src/session/session_outline.ts`:

- `sessionOutline(session, options)` — **L0**: по строке на unit (id, тип, текст запроса, статус
  сессии, чем закончился). Фокус показывается всегда; остальное — последние `k` unit'ов.
  Усечение явное: строка `k more (before <unitId>)` и курсор, без молчаливого обрезания.
- `unitOutline(session, unitId)` — **L1**: состояния (`move`) unit'а, каждое с островом,
  авторским `what`, признаком закрытия и `stop.why`; источник — `fold(unit.journal)` и
  существующие helpers обхода.
- «Результат» — терминальный маркер, а не вердикт: `stop.why`, `unactionable.why`, `open at
  <state>`, `suspended at <state>`, `abandoned at <state>`.

Обзор — чистая функция журнала сессии и журналов unit'ов; одинаковые события дают одинаковый
текст. Журналы `observer`-unit'ов в L0/L1 не попадают.

### 4.3. Session-unit и SessionAgent

`src/session/session_agent.ts` повторяет структуру `src/session/observer.ts`:

- `SESSION_BASE_PROMPT`: кто агент, когда отвечать вместо запуска задачи, как переформулировать
  задачу и когда уточнять или просить подтверждение.
- Корень — реплика пользователя: журнал session-unit'а пишет её как узел `request`; проекция
  рендерит её ведущим `user`-сообщением.
- Движок сеет журнал unit'а вызовом `outline` + `tool`-результатом (`origin: "engine"`), как 4a
  сеет RequestObserver.
- Цикл ограничен (по умолчанию 4 хода), одна операция за прогон. Read-only-вызовы исполняются и
  пишутся в журнал session-unit'а с `origin: "doxa"`/`"engine"`; предложение, отклонённое
  логосом, пишется в журнал session-unit'а, а не в журнал задачи.
- `projectSessionAgent` / `buildSessionMessages` пересобирают ленту из журнала unit'а; replay
  читает посеянный обзор, а не пересчитывает его.
- `runSessionAgent(deps, session, utterance, options) → { session, operation?, applied?, turns }`
  открывает/кладёт в стек session-unit, крутит цикл, снимает его и применяет операцию через
  логос.

`src/llm/session_agent.ts` — адаптер на AI SDK (zod-схемы + `createSessionAgentDeps`), в той же
форме, что `src/llm/observer.ts`. Инструменты:

| Инструмент | Вид | Аргументы |
|---|---|---|
| `read` | read-only | `{ path }` — создаёт reading-unit, возвращает preview + адрес |
| `unit` | read-only | `{ id }` (L1) |
| `state` | read-only | `{ unit, id }` (L2) |
| `turns` | read-only | `{ unit, id, from?, to? }` (ходы + рассуждение) |
| `body` | read-only | `{ unit, id, start?, end? }` (L4) |
| `search` | read-only | `{ unit, pattern, before?, after?, from?, count? }` (L4) |
| `respond` | операция | `{ text }` |
| `start` | операция | `{ text }` (переформулированный запрос) |

L0 на ленте: отдельного `outline` нет. `attempt` (L3) отложен. Бюджет обзора — `surveyLimit`
(по умолчанию 4) с сообщением «Decide now».

### 4.4. Операции и логос

`src/session/operations.ts` — `validateOperation(session, operation)` и
`applyOperation(session, operation, turn)`:

| Операция | Допустима, когда | Эффект |
|---|---|---|
| `respond` | всегда; текст непустой, до 4000 символов | записывает операцию и reasoning; деревья задач не меняются |
| `start` | текст непустой, до 4000 символов | снимает текущий фокус (`pop`), текст уходит в `pending`; будущий драйвер откроет новый запрос |

Каждая применённая операция пишется событием `operation` в журнал сессии; журнал
session-unit'а-источника хранит только его собственные вызовы и наблюдения. Отказ пишется
событием `refusal` (операция, причина, reasoning) в журнал сессии и виден в L0; дерево задачи
не меняется.
`start` не закрывает предыдущий unit: тот остаётся следом; `suspended`/`completed` — производные
статусы.

## 5. Порядок работы

1. **План-док.** Этот файл + EN-зеркало; запись в индексе `docs/README.md`.
2. **Статусы.** `types.ts`/`session.ts`; `attentionOf`; тесты на append-only, производный
   `completed`, `abandon` не закрывает состояние.
3. **Обзор.** `session_outline.ts`; L0/L1, усечение/курсор; тесты детерминизма и replay.
4. **Операции.** `operations.ts`; предусловия и отказы; журналы задач не тронуты.
5. **Session-unit и агент.** `session_agent.ts`, `llm/session_agent.ts`; посеянный обзор,
   ограниченный цикл, одна операция за прогон; интеграционные тесты со скриптованным агентом.
6. **Доки.** Обновить статус в `docs/session_concepts_ru.md`, `implementation_plan_ru.md`;
   финальный офлайн-прогон.

## 6. Инварианты тестов

- **Сессия:** журнал только растёт; `focus` — вершина стека; статусы производные; unit,
  закрытый `stop`, — `completed`, если не `abandoned`; `abandon` не пишет событий задачи.
- **Обзор:** L0/L1 детерминированы; фокус присутствует всегда; усечение явное с `k more` и
  курсором; журналы `observer` не протекают.
- **Операции:** отказ пишет событие `refusal` в журнал сессии, но не в дерево задачи;
  `respond` не меняет ни один unit; `start` снимает фокус со стека, оставляет старый unit
  следом и ставит текст в `pending`.
- **Session-unit:** посеянные вызов/результат имеют совпадающие id и `origin: "engine"`; replay
  читает их из журнала; read-only-инструменты ничего не пишут в журнал задачи; одна операция за
  прогон; отказ логоса не ломает сессию.
- **Проекция:** детерминирована; реплика — ведущий `user`-ход; session-unit не создаёт
  `stop`/`move` задачи.
- Команды: `npm run typecheck`;
  `SKEIN_LIVE=false npx vitest run --exclude 'tests/sandbox/**'`.

## 7. Критерии приёмки

- Typecheck и офлайн-набор зелёные; тесты покрывают §6.
- Session-unit не пишет `move`/`stop`/`plan` ни в одно дерево задачи.
- Статусы производятся из журналов; ничего не хранит вердикт.
- L0/L1 ограничены и детерминированы; одна сессия даёт один и тот же обзор.
- Операция применяется только после проверки логосом; отказ виден и безвреден.
- Ни одного live/bench-прогона не сделано.

## 8. Открытые вопросы

- **Драйвер.** Срез заканчивается на `runSessionAgent`; цикл «реплика → операция → запуск
  задачи» — следующий шаг.
- **`respond`.** Ответ записывается в журнал сессии и показывается в L0-следе.
- **L0.** Показывается целиком; при переполнении контекста — явное предупреждение.
- **`revise`.** Отложено: пользовательский факт, привязанный к unit'у/состоянию.
- **Словарь session-unit'а.** Используется ограниченный цикл вместо полной машины состояний
  `survey/interpret/decide`; это повторяет 4a и может быть заменено тем же IR позже.

## 9. Откат

- Статусы, обзор, операции и session-agent входят отдельными коммитами.
- Их удаление оставляет каркас сессии 4a нетронутым; `runAgent` не меняется.
- Миграция журналов не нужна: новые события сессии появляются только в новых сессиях.
