# Skein — план инспекции: показ `verified` и статус-осознанный `query`

> Английское зеркало — `docs/plans/archive/context_inspection_plan.md`.

Статус: реализовано (пункты A–D); см. `tests/ir.test.ts` и `tests/loop.test.ts`.

## Цель

Установленные факты (`verified`) и провенанс вердиктов не должны пропадать
бесследно — но без возврата к «ленте сообщений» и без зоопарка инструментов.

## Границы

Входит: секция `verified` в проекции; статус-осознанный `query`; чтение
вердиктного следа; ограниченные выдержки вывода команд со спил-указателем.

Не входит: чтение сырого журнала (`Event[]`), хранение содержимого внутри IR,
новые инструменты кроме `query`, сырые лог-дампы в контекст.

## A. Секция `verified` в `Context`

- `frontier` получает поле `verified: string[]` — зеркально к `rejected` (одна
  строка `id: label`).
- Источник: узлы `kind === "claim"` со статусом `verified` (`state.statuses`),
  отсортированные по `seq` убыв., ограниченные N (как `recent` через `tail`).
- Файлы: `src/ir/project.ts` (интерфейс `Context` + сборка), `docs/ir.md` и
  `docs/ir_ru.md` §4.
- Обоснование: «что уже установлено» всегда релевантно, значит место в проекции;
  детерминированно, без надежды на дисциплину модели.
- Тесты: `tests/ir.test.ts`, блок `record_check` — сейчас на pass проверяется
  только `frontier.claims === []`; добавить
  `frontier.verified === ["c1: off-by-one in loop"]`. Добавить тест на
  порядок/ограничение; расширить тест `project`.
- Открытый вопрос: N и правило отбора. Простое — последние N. «Идейное» — только
  достижимые от открытой цели (provenance-релевантность пока не реализована).
  Начать с простого.

## B. Статус-осознанный `query`

- Проблема: `query` возвращает узел (`src/tools/index.ts:264`), а статус лежит
  отдельно в `state.statuses` / `state.edgeStatuses` — поэтому «покажи verified
  claims» невозможно.
- Схема (`src/llm/schemas.ts:29`): вместо `selector: z.string()` — структурные
  селекторы:
  - `id?`; `kind?`; `status?` (валидировать через `z.enum(STATUSES)` из
    `src/ir/types.ts`); `edgesOf?` с необязательным `edgeKind?`.
- `executeAction` (`src/tools/index.ts:264`): фильтровать по состоянию, склеивая
  узел со статусом; отдавать легальную форму (`id, kind, label, status`), а не
  сырой `Node`.
- Промпт (`src/loop/propose.ts:24`): описать формы `query`.
- Правила: read-only (`events: []`, проверяется тестом); лимит строк и обрезка
  вывода; никаких сырых событий журнала.
- Тесты: `query { kind: "claim", status: "verified" }`; `query { id }` возвращает
  узел + рёбра; `query` не пишет события.

## C. Вердиктный след (провенанс)

- Данные уже есть: `record_check` сохраняет `{ command, verdict, output,
  claimIds }` (`src/ir/graph.ts:101-108`), `output` обрезан до 8000
  (`src/tools/index.ts:222-228`); `verifies`-рёбра связывают
  `observation → claim`.
- Добавить селектор `verdictOf: <claimId>`: возвращает чеки по claim и связанные
  наблюдения, как `claim → verifies-edge → observation → check`.
- Тесты: случаи pass и fail; при отсутствии данных — честное «нет данных».

## D. Вывод команд: ограниченная выдержка + спил-указатель

Два шага, оба в объёме.

### D1. Выдержка head+tail (сразу)

- Проблема: `clip` держит только начало (`src/tools/index.ts:17`), из-за чего
  теряется итог ошибки в конце вывода тестов, а маркер сообщает лишь число байт.
- Заменить head-only обрезку на детерминированную выдержку head+tail и для текста
  хода, и для записанного вывода. Механически, не LLM-саммари — то же правило,
  что держит проекцию дешёвой (`docs/concepts.md`).
- Маркер обязан быть видимым и восстановимым: сколько опущено и где лежит полный
  вывод.

### D2. Спил в `.skein/` + `outputRef`

- Если вывод превышает лимит выдержки, полный вывод писать в
  `.skein/logs/run-<turn>.log`. `.skein` уже в `SKIP_DIRS`
  (`src/tools/workspace.ts:34`), поэтому `list`, `grep` и constraint-гард его
  игнорируют.
- Записывать `outputRef` в payload наблюдения и в `record_check`; заполнить уже
  объявленное, но неиспользуемое поле `outputRef` у проверочного провенанса
  (`src/ir/types.ts:38`).
- Доступ — существующим `read { path, start, end }`; новый инструмент не нужен.
- Добавить `.skein/` в `.gitignore` (вывод может содержать секреты; сейчас
  игнорируется только `*.log`).

### Правила и оговорки

- Полный вывод никогда не входит в IR: в IR — указатель плюс ограниченная
  выдержка.
- Детерминизм `fold` не затронут; спилы — эфемерные побочные эффекты, поэтому
  воспроизводимость сессии зависит от них. Retention/очистка — вопрос lifecycle
  (ограничить, чистить по завершении прогона).
- Тесты: выдержка показывает оба конца и маркер об опущенных строках; файл спила
  существует и читается оконным `read`; `.skein` исключён из `list()`/`grep()`;
  `record_check` несёт `outputRef`.

## Инварианты

- `project` остаётся чистой функцией состояния; `verified` выводится только из
  `fold(events)`.
- Полный вывод команд никогда не входит в IR; хранится только указатель плюс
  ограниченная выдержка.
- `query` остаётся чистым (ничего не пишет) → append-only и детерминизм целы.
- Статус берётся из `state.statuses` / `state.edgeStatuses`, никогда из `Node`.
- Секция `verified` не показывает содержимого и не воскрешает `stale`-факты как
  активные.

## Порядок работ

1. `verified` в `frontier` + тесты + доки.
2. Статус-осознанный `query` (схема, `executeAction`, промпт, тесты).
3. Расширение `verdictOf`.
4. Вывод команд: выдержка head+tail (D1), затем спил + `outputRef` (D2).

## Рядом, вне объёма

- Настоящая provenance-релевантность (путь от цели).
- Мёртвый `frontier.observations` (собирается по `verifies`-рёбрам к открытым
  claims, которых у таких рёбер не бывает).
