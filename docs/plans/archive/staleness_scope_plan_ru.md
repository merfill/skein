# Skein — план охвата устаревания (дедуп свидетельства и транзитивность)

> Английское зеркало — `docs/plans/archive/staleness_scope_plan.md`.

Связанные: `docs/design_review_ru.md` (R3b),
`docs/plans/archive/check_soundness_plan_ru.md`, `docs/plans/observation_plan_ru.md`.
Общий план — `docs/plans/implementation_plan_ru.md`.

Статус: реализован (см. §8).

## 1. Проблема

R3b спрашивал, обесценивает ли проверку изменение импортируемого модуля
(«транзитивная устарелость»). Разбор кода показывает, что уже да: `run` снимает
версии **всех** отслеживаемых файлов (`workspace.list()`, `.skein` исключён) и
записывает их свидетельством проверки; `mutate` гасит любое ребро `verifies`, в
чьём свидетельстве есть изменившийся `ref` с другой версией. Значит изменение
где угодно инвалидирует проверку — звуково, но грубо. Транзитивность покрыта
сверхприближением, а не графом импортов.

Что реально оставалось:

- доки всё ещё звали R3b открытым;
- свидетельство **дублировалось** трижды: в payload наблюдения, в
  `record_check` и в провенансе каждого ребра `verifies` (по claim). Копия в
  `record_check` не читалась; живыми были копии в рёбрах.

## 2. Решение

- **Транзитивность:** оставить снимок всего воркспейса — он даёт звуковую
  транзитивность. Точность (не гасить на несвязанные изменения) требует графа
  зависимостей и откладывается сознательно — без трассировки чтений сужение
  свидетельства рискует неполнотой.
- **Дедуп:** свидетельство живёт **один раз**, в payload наблюдения-источника.
  Ребро `verifies` и `record_check` его больше не несут; `mutate` и сверка
  резолвят его через `edge.from`.

## 3. Дизайн

- `src/ir/types.ts` — убрать `witness` из провенанса `check`.
- `src/ir/events.ts` — убрать `witness` из `record_check` и схемы провенанса
  `check`.
- `src/tools/index.ts`, `run` — прикладывать свидетельство только к payload
  наблюдения.
- `src/ir/graph.ts` — `witnessOf(state, edge)` резолвит свидетельство из
  наблюдения-источника; `mutate` использует его для рёбер `verifies`.
- `src/loop/observe.ts` — сверка резолвит активные `ref` тоже через `witnessOf`.
- Доки — `docs/plans/archive/check_soundness_plan.md`, `docs/ir.md` / `ir_ru.md`,
  `docs/design_review.md` / `_ru`.

## 4. Проверка

- `npm run typecheck`; `npm test`.
- Существующие тесты инвалидации переписаны: свидетельство — в payload
  наблюдения; инвалидация при изменении свидетеля и повторная верификация попрежнему
  проходят; сверка по-прежнему замечает дрейф свидетелей.

## 5. Инварианты

- Звуковость не меняется: изменение любого файла-свидетеля гасит проверку.
- Журнал остаётся append-only; свидетельство пишется один раз, в наблюдении.
- `project` и `fold` остаются чистыми и детерминированными.

## 6. Границы

- **Точность** (не гасить на несвязанные изменения) отложена: нужен граф
  зависимостей файлов, а суженное свидетельство неполно без знания, что читала
  команда.
- Свидетельство в payload наблюдения читается типизированным кастом, как и
  другие payload.

## 7. Порядок работ

1. Убрать дубль свидетельства из types/events.
2. Резолвить его через наблюдение в `mutate` и `reconcile`.
3. Обновить писателя `run`.
4. Тесты и доки.

## 8. Статус

Реализовано. Свидетельство хранится один раз, в payload наблюдения; `run` больше
не прикладывает его к `record_check` и `verifies` (`src/tools/index.ts`);
`witnessOf` резолвит его для `mutate` и сверки (`src/ir/graph.ts`,
`src/loop/observe.ts`). `npm run typecheck` чист, `npm test` проходит (44 теста).
Доки обновлены: `check_soundness_plan`, `ir`, `design_review`.
