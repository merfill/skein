# Skein — план редукции цели (минимальная цель)

> Русское зеркало `docs/plans/goal_reduction_plan.md`.
> Статус: **планирование — ждём утверждения.** Без кода до «ок» владельца.
> Заменяет части goal/plan/closure из `docs/plans/traversal_stack_spec_ru.md` и гейт по
> критерию в `docs/ir_semantics_ru.md` §2.2/§4.3; затрагивает `AGENTS.md`.

## 1. Назначение

Сегодня цель несёт слишком много: `done_when` (команда-критерий), отдельный `step`, список
id `revises` и выставленный `state`, а движок гейтит `stop` по `exitCode` прогона критерия.
Из-за этого модель **до исследования** обязана закоммитить команду проверки (на свежем
запросе доступны только `create_goal`/`decline`), а неверная команда отравляет прогон —
регрессия `fix-ocaml-gc` это 36 из 56 ходов возни ровно из-за этого. Редукция оставляет
только то, чем цель на самом деле является: что делать, зачем, набросок и план.

## 2. Целевая модель

**Цель** = `what` (обязательно) + `why?` + `sketch` (обязательная строка) + **контейнер
плана**.

- **`sketch`** — короткая свободная строка; заметка модели, чтобы не потеряться (прежний
  `plan`, переименован).
- **Контейнер плана** создаётся вместе с целью и **сразу заполняется первым пунктом
  плана**, который становится текущим и растёт по мере добавления.
- **Каждый пункт плана — контейнер `alternatives`.** Его первый элемент — сам пункт:
  команда или цель. Движок исполняет текущий элемент и возвращает результат вместе со всем
  контекстом (обычный «ReAct-на-месте» из `traversal_stack_spec_ru.md` §3).
- После результата модель может:
  1. добавить **следующий пункт плана**;
  2. `stop` — следующий пункт плана станет узлом `stop`, запускается процедура закрытия
     цели;
  3. создать **альтернативу** текущему пункту — цель или команду — в его контейнер
     `alternatives` (append-only; последняя — текущая).
- **Закрытие динамическое.** `stop` добавляет пункт плана `stop` и ребро `has_stopped`.
  Никакого прогона критерия, никакого оракула по exit code, никакого гейта `check_not_run`.

Закрытость читается из **рёбер**, не хранится: цель закрыта ⇔ есть ребро `has_stopped`;
пункт плана выполнен ⇔ его текущая опция — исполненное действие или закрытая цель. IR
остаётся монотонным (принцип: контекст — проекция, факты только добавляются).

## 3. Редукция атрибутов

| атрибут | сейчас | после | почему |
|---|---|---|---|
| `what` | обязат. | **обязат.** | оставить |
| `why` | опц. | **опц.** | оставить (гипотеза) |
| `plan` (строка-набросок) | обязат. | **`sketch`, обязат.** | оставить, переименовать; заметка «не потеряться» |
| `step` | обязат., отдельное поле | **убрать** — сев = первый пункт плана | избыточно: пункт плана и есть последний элемент контейнера |
| `done_when` | обязат. команда-критерий | **убрать** | слепой коммит; закрытие — `stop`, решается в процессе |
| `exitCode`-критерий | `run { target }` → гейт pass/fail | **убрать** | код возврата — обычный вывод, не оракул закрытия |
| `revises` (список id) | параметр `create_goal` | **убрать** | текущий пункт неявен (последний); история — в событиях |
| `state` (`open`/`executed`/`stopped`) | производное, **выставлено** на узлах/пунктах | **убрать из модели** | закрытость = `has_stopped`; выполненность = `produces` — монотонно, выводится по запросу |
| `checkReady` | поле проекции | **убрать** | следствие критерия |
| `nextAction` | поле проекции | **убрать** | «текущий пункт — последний» уже правило |
| `background` / `job` (`run`) | параметры `run` + механика jobs | **убрать** | не часть модели цели (владелец: не слышал о таком) |
| спецкейс «корневая цель» / `interpreted` | цель запроса фиксирована-один-раз и привилегирована | **убрать** — обычная цель у запроса | «корневой цели» нет; цель у запроса — просто цель |
| `alternatives` | контейнер | **оставить** (теперь явно на каждом пункте) | ветвление/ревизия — механизм восстановления, убрать нельзя |
| `decline` / `unactionable` | оператор + узел | **оставить** | нужен для не-действенного запроса |

## 4. Поверхность операторов после редукции

- `create_goal { what, why?, sketch, command }` — у **запроса** это интерпретация; у
  **открытой цели** — **подцель-альтернатива** текущему пункту. Засевает контейнер плана
  первым пунктом (`command` = первый пункт плана / команда). `command` — не особый «step»:
  это просто первый пункт плана.
- `apply { … }` (`read` / `grep` / `list` / `edit` / `write` / `run` / `fetch` /
  `apply_patch`) — шаг плана. `run` теряет `target`, `background`, `job`: это одна простая
  команда; применение другой команды к текущему пункту добавляет её как **альтернативу**.
- `stop { why? }` — добавляет пункт плана `stop` и закрывает цель (без гейта по критерию).
- `decline { why? }` — не-действенный запрос (оставить).
- `recall { id }` / `search { id, pattern }` — адресация сохранённого тела (оставить).

> **Решено:** первый пункт плана несёт `command` — `create_goal { what, why?, sketch,
> command }`; `label` прежнего `step` отбрасываем.

## 5. Что явно отложено (другая проблема)

- **Детекция циклов**, преждевременного `stop` и «нет прогресса». Владелец отложил; редукция
  намеренно не заменяет гейт критерия другим гейтом.
- Политика вытеснения рабочего множества (`traversal_stack_spec_ru.md` §11).

## 7. Стадии и проверка

Каждая стадия — отдельный зелёный коммит.

1. **Схема + типы + парсер действий** (`schemas.ts`, `tools.ts`, `types.ts`).
   `npm run typecheck`.
2. **Граф + обход + classify** (закрытие и фронтир без критерия).
   `tests/ops/{applicable,traversal,derivation,stop}.test.ts`.
3. **`executeAction`** (сев `create_goal`, `run`, `stop`).
   `tests/ops/{create_goal,apply,stop}.test.ts`, `tests/tools.test.ts`.
4. **Проекция + промпт**; `tests/ir.test.ts`, `tests/prompt.test.ts`.
5. **Доки + реестр покрытия + `AGENTS.md`**; `tests/coverage.test.ts`.
6. **Полный offline-гейт**: `npm run typecheck` и
   `SKEIN_LIVE=false npx vitest run --exclude 'tests/sandbox/**'`.

Опционально после гейта: один дешёвый живой вызов `create_goal`, чтобы подтвердить
редуцированную форму (нет `done_when`/`step`; план засеян первым пунктом), затем живой
`fix-ocaml-gc` — подтвердить, что возня ушла (решение владельца, по стоимости).

## 8. Последствие, которое принимаем

Закрытие переезжает с прогона критерия (`logos` читает exit code) обратно на `stop` доксы.
В этом и смысл редукции, и поэтому детекция циклов/преждевременного стопа — **отдельная,
более поздняя** проблема (§5).
