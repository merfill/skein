# Skein — план сокращения LLM-турнов и формата контекста

> Русское зеркало `docs/plans/step_reduction_plan.md`.
> Основание — разбор сравнительных прогонов `ref-localize` (`docs/benches/bench_report_ru.md` §4.5)
> и обсуждение принципа докса/логос. Затрагивает `docs/ir_ru.md`,
> `docs/system_prompt_ru.md`.

## 1. Методология стоимости

Смешивать «ходы доксы» и «операции логоса» нельзя:

- **LLM-турн** (обращение к доксе) — единственная статья расходов: токены, кэш,
  латентность.
- **Операция над IR** (закрыть цель, проставить `verifies`, поднять курсор плана,
  вернуть фокус, пометить `addressed`) — детерминирована и **бесплатна**.

Считать IR-операции «шагами» — методологическая ошибка. В прежнем коде
`create_goal`/`complete`/`query`/`run target` были реализованы как ходы доксы, поэтому
они стоили; но логически это работа логоса, которую движок обязан делать сам.
(`complete` с тех пор удалён — см. A2; `query` и `run target` остаются ходами доксы.)

**Метрики:** LLM-турны; input/output-токены; cache%; `reasoning_tokens` на ход
(индикатор лишнего обдумывания); wall-time. Reward — контрольный инвариант.

Данные `ref-localize` (§4.5): полезная работа у Skein ≈ 5.75 действия против 5.7 у
opencode; вся разница (≈6.25 «шага») — служебные ходы, дублирующие работу логоса.
На ход приходится ~7.2k токенов константы (system 19 227 симв. + tools 9 161 симв.).

## 2. Принцип

> Докса за турн предлагает **один оператор**; движок применяет **детерминированное
> замыкание дерева до неподвижной точки**. Число IR-операций в замыкании не
> ограничено. Каждая замкнутая цель несёт провенанс чека (инвариант «нет verified без
> check provenance»).

Граница: **objective**-цель закрывается вердиктом чека (логос); **arbiter**-цель —
только внешней приёмкой; запуск команды (сайд-эффект) инициирует докса. Докса не
закрывает цели (`complete` удаляется, A2).

## 3. Часть A — замыкание логоса

Порядок работ: **A3 → A2 → A4 → A5** (A1 и A4 — сняты).

### A1 — objective-замыкание (снято)

> **Снято** в `docs/plans/archive/plan_stepwise_redesign_ru.md` (шаг 2.5, решение §3(a)):
> при строго пошаговом обходе пункты плана — только действия, вложенных objective-цепочек
> с общим критерием нет, `closeAncestors` становится мёртвым. Код удалён совместно с
> шагом 2.

**3.1 Семантика.** Проходящий objective-чек верифицирует цель в фокусе **и всех её
предков по плану** с тем же `done_when.command`, если все прочие пункты их планов уже
успешны. Провенанс — тот же чек (тот же witness). Subjective-цели замыкание не трогает.

**3.2 Реализация.** `src/ir/graph.ts`:
- приватная `itemSettled(state, itemId)` — для `goal` predicate `achieved`/`achieved_under`,
  для `action` `executed`, с учётом alternatives;
- `closeAncestors(state)` — BFS вверх от целей чека по контейнерам плана; при совпадении
  команды и успешности прочих пунктов — ребро `verifies` `chk→G` (id `${checkId}:c:${G}`),
  провенанс чека, идемпотентно;
- в `fold`: `derivePredicates(state); closeAncestors(state); derivePredicates(state);`.

Почему в `fold`: чистая функция журнала (детерминизм `same events → same Context`);
покрывает любой `record_check`, включая `userAcceptance`; инвариант
`achievedWithoutCheck` видит синтезированные рёбра; обход (`focusEvents`) сам каскадно
поднимает фокус, а `progressNode` останавливает цикл — новых событий доксы не нужно.

**3.3 Промпт.** B7 (`src/loop/prompt/blocks.ts`): интерпретация с тем же критерием
закрывается движком автоматически; отдельный чек — только при ином критерии.

**3.4 Тесты.** `tests/ops/derivation.test.ts` (positive; иной command — negative;
невыполненный пункт — negative; вложенность; `under` → `achieved_under`).
`tests/ops/apply.test.ts` — интеграционный: `create_goal` с планом →
`complete(stage1)` → `check(stage2)` → root `achieved`, request `addressed`, второго
чека нет. Live — существующие сценарии + `achievedWithoutCheck`.

**3.5 Проверка.** `npm run typecheck`; `SKEIN_LIVE=false npx vitest run`;
`SKEIN_LIVE=true npx vitest run tests/live/scenarios.test.ts`;
`SKEIN_CASES=fixtures/synthetic npx tsx bench/run.ts ref-localize-{on,off}`.

**3.6 Эффект.** −1 турн в каждом багфиксе (дублирующий финальный чек); меньше прогонов
команд и полных хэшей воркспейса. Reward не меняется.

**Статус: отменено** — код удалён вместе с шагом 2
(`docs/plans/archive/plan_stepwise_redesign.md` §2.5); заметка ниже исторична.
Подтверждено прогоном
`ref-localize-on` (2026-10-07): `checks=1` вместо 2, `steps=10`, reward 1; замыкание
`chk:55→w:goal:2`, root `achieved`, request `addressed`. Остаётся повторный A/B §4.5.

### A2 — структурное замыкание, отказ от `complete` (ядро)

**Семантика.** Состояние цели выводится из поддерева, а не утверждается доксой:
- цель с планом **исполнена**, если **все** пункты плана исполнены;
- **опровергнута**, если в поддереве есть `refuted`, не заменённый альтернативой;
- цель с **пустым планом** — исполнена (вакуумная истина; такие цели не должны
  создаваться);
- objective-цель — по вердикту своего чека (как сейчас);
- оператор `complete` **удаляется**: докса цели не закрывает.

**Реализация.** Структурное правило в `goalPredicate` (`src/ir/graph.ts`); удаление
`complete` из `schemas.ts`, `tools.ts`, `classify.ts`, `applicable`, B7 и из
`latestComplete`/`closes`-семантики; обновление тестов и документов.

**Эффект.** −2 вызова (стадии `reproduce`/`locate` больше не закрываются вручную).

**Риск.** Ядро семантики; перепроверить инварианты, ops-тесты, live-сценарии.

**Статус:** реализовано. `done_when` = `objective` | `arbiter`; `complete`/`closes`
удалены из типов, схемы, инструментов, классификатора, `applicable`, проекции и
`goalPredicate`; B3/B6/B7/B13 переписаны (план = действия + одна objective-цель).
Offline-тесты обновлены (240 passed). Живой `ref-localize-on`: reward 1, `steps=9`,
`complete` отсутствует. A3 сделано ранее; остаются A4 (гипотеза + действия одним
вызовом) и A5 (авто-чек).

### A3 — рабочее множество: не вытеснять доказательства

**Проблема.** Тело diff (479 симв.) вытесняется **не по размеру**, а по scope:
`levelIds = current.branch` (`src/loop/graph.ts`) — закрытая стадия уходит с ветки,
тело пропадает; в индексе `calls` от него остаётся заметка, обрезанная до **120** символов.

**Реализация.** Scope рабочего множества = тела под открытыми целями пути **плюс тела
недавно закрытых стадий** (`HELD_TURNS = 6`); лимиты `MAX_HELD = 5` / `HELD_CHARS = 16 000`
не меняем. `callNote` (`src/ir/project.ts`) 120 → **512** символов.

**Эффект.** −1 вызов (`query`) в on/off.

### A4 — гипотеза + первые действия одним вызовом

**Идея.** `create_goal` несёт гипотезу и план; движок в том же ходе исполняет первые
пункты-действия плана (а не платим отдельный ход за `create_goal`, а затем за `run`).

**Реализация.** Расширение `create_goal`/`executeAction`; опирается на A2 (пункты-действия
и структурное замыкание).

**Эффект.** Ведущие action-пункты нового плана исполняются движком в том же ходе (до
первой цели; кап `AUTO_RUN_ACTIONS = 4`), так что `create_goal` + разведочные команды —
один вызов.

**Статус: отменён (откатан).** Авто-прогон нарушает пошаговость (I4) и **породил
воронку** на длинных задачах (`docs/benches/bench_report_ru.md` §4.4, прогон `2026-10-07__16-42-30`:
все 9 триалов `llm_error`): план исчерпывался в том же ходе, а у `arbiter`-цели с
исчерпанным планом `applicable` предлагал только `create_goal` → вложенные цели.
Откат — `docs/plans/archive/plan_stepwise_redesign_ru.md` шаг 1 (`AUTO_RUN_ACTIONS` и цикл
удалены). Исторические метрики ниже оставлены для контекста.

Исторически (при A4): живой `ref-localize-on`: **steps 5** (было 9), prompt 45.6k
(было 77.5k), reward 1; `ref-localize-off`: **steps 5** (было 11.7), prompt 52.6k (было
120.7k), reward 1. Онлайн-тесты, писавшие под пошаговое исполнение, обновлены.

**Баг A4 (исправлен).** Авто-прогон ведущего действия `node --test` совпадал с
`done_when.command` цели, и ветка `run` **неявно** превращала его в чек — цель
опровергалась на шаге воспроизведения (трейсы `09:31`, `09:48`: `record_check` fail до
фикса). Исправление: вердикт выносит **только явный чек по цели** (`run {target}`),
совпадение команды больше не повышает run до чека (`docs/plans/traversal_stack_spec.md`
§9). Offline: 240 passed. Фикс **оставлен** и после отката A4 — вердикт всегда выносит
явный чек по цели.

### A5 — авто-прогон критерия objective-цели (отклонено)

Движок сам запускает `done_when.command`, когда план objective-цели выполнен.
**Реализовано и проверено, затем откачено.** Причина: `checkReady` срабатывает
**преждевременно** — цель с планом из действий «готова» сразу, как только действия
исполнились (в т.ч. авто-прогоном A4), и движок тут же проверяет критерий. На
`ref-localize-on` это дало лавину рефутаций и в одном прогоне ушло в `maxTurns`
(24 шага, 14 целей); в остальных — 7–8 вместо 5. Мир/решение — за логосом (как в A4),
но сам триггер «план выполнен» слишком грубый; нужен признак «работа над целью
действительно завершена», которого у движка нет. Гипотезу отклонили; код A5 убран.

**Открыт (переформулирован):** что считать «цель готова к проверке» так, чтобы не
рефутить интерпретацию на промежуточном шаге. Кандидат — только objective-цель, чей
план завершился **прохождением дочернего чека** (а не исполнением действий), т.е.
проверка поднимается по дереву, а не запускается по «плану из действий».

## 4. Часть B — формат контекста (последний пункт)

**4.1 Проблема.** Сейчас на каждый ход шлётся свежая пара
`[system, user(JSON-проекция)]` + `tool_choice: required` — **без ролей
assistant/tool**. Модель не видит свою предыдущую ленту вызовов/результатов; состояние
реконструируется из JSON. Гипотезы: (а) off-distribution формат повышает
`reasoning_tokens`/ход; (б) нет приора «tool result следует за tool call» → лишние
перепроверки; (в) кэшируется только префикс system+tools, проекция не кэшируется.

**4.2 Варианты упаковки в привычную историю.**
- **A (текущий):** `[system, user(JSON)]`.
- **B (транскрипт):** `[system, user(task), assistant(tool_call)/tool(result) × K,
  user(frontier)]` — рендер ограниченной проекции как обычного диалога.
- **C (гибрид):** компактная JSON-проекция + короткое окно транскрипта.

Рендеры — чистые функции событий (детерминизм сохраняется), окно K ограничено
(контекст не растёт как лента).

**4.2a Телеметрия + A+ (стабильный префикс) — измерено; A+ отклонён.** Reasoning-токены
не собирались: `UsageLike` (`bench/metrics.ts`) читал только input/output/cache. Теперь
берётся `output_token_details.reasoning` (fallback
`response_metadata.usage.completion_tokens_details.reasoning_tokens`);
`TurnMeter`/`TurnRecord` несут `reasoningTokens`, строки `SKEIN_TURN`/`SKEIN_METRICS`
в `bench/run.ts` и `langgraph/graph.ts` его включают, `bench/agents_compare.ts` печатает
`reason`.

Пробовали A+ (перестановка ключей: стабильные поля перед `state`/`cursor`/`chosen`,
волатильные слои в хвост, `calls` по возрастанию) на `ref-localize-on`, n=3. Префикс
**не** удлинился: средний общий префикс сериализации между ходами ~30–40% в обе стороны.
Живые прогоны хуже — A: steps 7/7/7, `reason` 210/372/505, cache 84/83/73%; A+: steps
9/8/7, `reason` 712/752/429, cache 64/71/70%. Причина: `path` идёт первым и несёт
волатильные `state`/план, поэтому порядок ключей внутри узлов префикс не удлиняет (а
перенос `lastResult` вниз, похоже, стоит хода). A+ откачен; **телеметрия оставлена**.
Настоящий префикс требует разделения stable/volatile (неизменный бриф перед фокусом) —
свёрнуто в варианты B/C ниже.

**4.2b B (транскрипт) — прототип.** Транскрипт — это текущая ветка, а не глобальный
журнал: `system`, неизменный бриф (request + constraints), шаги ветки как пары
`assistant(call)/tool(result)` в хронологическом порядке и волатильный борд в конце.
Короткие тела результатов — инлайном; длинное тело остаётся адресуемым по `id` (`query`) —
существующее правило рабочего множества/хранения не меняется. История ограничена выбранной
интерпретацией, поэтому шаги провалившейся альтернативы не разворачиваются — в `path`
виден только её маркер (`refuted`/`abandoned` с `why`); при откате префикс до узла
развилки не меняется, перегенерируется только суффикс. `assistant` несёт только tool call
(без `thought`, B.3). Включается `SKEIN_CONTEXT_FORMAT=transcript` (по умолчанию `json`);
бенч и live-харнесс теперь меряют реальный размер промпта (`promptText`). Закреплено
`tests/prompt.test.ts` («context format: transcript»).

**4.3 A/B-эксперимент.** Кейсы: `ref-localize-on` + один live-сценарий. Сравнить
варианты A/B(/C) по LLM-турнам, input/output, cache%, `reasoning_tokens`/ход, reward.
Гипотеза: B снижает reasoning/ход и повышает cache% при том же reward.

**Оговорка по метрике (для полного сравнения с opencode, отложено).** opencode отдаёт
reasoning отдельно: в локальном JSON есть `tokens.reasoning` рядом с `tokens.output`, а
`tokens.total = input + output + reasoning + cache.read`. `tools/measure.ts` в плагине
суммирует только `tokens.output`, поэтому кэшированный `out` у opencode **без** reasoning;
у Skein LangChain `output_tokens` его **включает**. При сравнении суммировать
`tokens.reasoning` из сырого `opencode.txt` и сравнивать reasoning↔reasoning (и никогда
`out`↔`out`). Полные прогоны opencode на `ref-localize-on` и `multi-bug-calc` отложены.

**4.4 Что решить до реализации.** Размер окна K; генерация tool-сообщений и их id;
соотношение с бэклогом «стабильный префикс проекции»
(`docs/plans/implementation_plan_ru.md` §4).

**Статус:** телеметрия реализована и используется; A+ измерен и отклонён (откачен).
B (транскрипт) реализован за `SKEIN_CONTEXT_FORMAT`; живой A/B (json vs transcript) —
следующий. C остаётся.
