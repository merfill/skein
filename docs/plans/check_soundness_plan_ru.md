# Skein — план достоверности проверок (изменение обесценивает верификацию)

> Английское зеркало — `docs/plans/check_soundness_plan.md`.

Связанные: `docs/design_review_ru.md` (R3), `docs/concepts_ru.md` (первый
принцип), `docs/ir_ru.md` §3. Общий план — `docs/plans/implementation_plan_ru.md`.

Статус: реализован (см. §8).

## 1. Проблема

Утверждение становится `verified` через `record_check` (`src/ir/graph.ts:112`),
но проверка не запоминает версии файлов. `mutate` помечает `stale` только рёбра
чтения (`src/ir/graph.ts:89`), поэтому факт `verifies` / `check` не
инвалидируется. Следствие: после правки кода утверждение, подтверждённое на
старой версии, всё ещё показывается как подтверждённое в `frontier.verified`
(`src/ir/project.ts:80`). Это нарушает инвариант «устаревший факт никогда не
подаётся как активное содержимое» и первый принцип — вердикт должен
прослеживаться до версии, на которой получен.

## 2. Решение

Дать проверке ту же память о версиях, что уже есть у чтения.

- Проверка записывает **свидетельство**: пары `ref → version`, на которых
  получена.
- `mutate` расширяет правило на рёбра `verifies`: ребро, в чьём свидетельстве
  есть изменившийся `ref` с другой `version`, становится `stale`.
- Проекция показывает утверждение подтверждённым только при живом (не `stale`)
  ребре `verifies`; иначе утверждение попадает в новую секцию
  `frontier.invalidated` (одна строка), но никогда в `verified`.

Инвалидация остаётся **производным** переходом: меняется производный статус
ребра в `State`, но не журнал. Статус утверждения по-прежнему пишет только
арбитр (`record_check`); `mutate` никогда не переписывает статус утверждения.
Журнал остаётся append-only; исходные факты (`add_edge`, `record_check`) не
трогаются.

Отвергнуто: демутация узла-утверждения на `mutate` (перенесла бы логос на статус
узла и потребовала `set_status`). Она монотонна при записи событиями, но
смешивает «утверждение ложно» с «доказательство устарело» — достоверно известно
только второе.

## 3. Дизайн

- `src/ir/types.ts` — провенанс `check` получает
  `witness?: { ref: string; version: string }[]`.
- `src/ir/events.ts` — `record_check` и схема провенанса `check` несут `witness`.
- `src/tools/index.ts`, `run` — перед записью снять версии всех отслеживаемых
  файлов (`workspace.list()` + `workspace.version`, `.skein` исключён); приложить
  свидетельство к payload наблюдения, к `record_check` и к каждому ребру
  `verifies`.
- `src/ir/graph.ts`, `mutate` — помечать `stale` и рёбра `verifies`, если в их
  свидетельстве есть изменившийся `ref` с другой `version`.
- `src/ir/project.ts` — `frontier.verified` требует живого ребра `verifies`;
  добавить `frontier.invalidated` (id + причина) для подтверждённых утверждений,
  у которых все рёбра устарели.
- `src/tools/index.ts`, `query` — фильтр по статусу и `verdictOf` должны
  учитывать живость ребра, чтобы `status: "verified"` не показывал
  инвалидированное утверждение.
- Доки — `docs/ir.md` / `ir_ru.md` (инструмент→события, переходы статусов,
  проекция), `docs/design_review.md` / `_ru` (отметить R3a закрытым).

## 4. Проверка

- `npm run typecheck`; `npm test`.
- Новые тесты: `run` на `v2`, затем `mutate` к `v3` → утверждение не в
  `frontier.verified`, а в `frontier.invalidated`; повторный успешный `run`
  снова подтверждает; `verifiedWithoutCheck` по-прежнему выполняется.

## 5. Инварианты

- Журнал append-only; меняется только производный статус.
- `verified` — только с провенансом `check`.
- Устаревшее доказательство не показывается как активное.

## 6. Границы

- Транзитивная зависимость модулей (правка импортируемого файла) вне области:
  свидетельство — это снимок на момент прогона, а не граф импортов.
- Внешние изменения — в `docs/plans/observation_plan_ru.md`.

## 7. Порядок работ

1. Типы / события: свидетельство.
2. `run`: приложить свидетельство.
3. `mutate`: гасить рёбра `verifies`.
4. `project` / `query`: фильтр живости + `invalidated`.
5. Тесты + доки.

## 8. Статус

Реализовано. Свидетельство — в провенансе `check` и в `record_check`
(`src/ir/types.ts`, `src/ir/events.ts`); `run` его прикладывает
(`src/tools/index.ts`); `mutate` гасит рёбра `verifies` (`src/ir/graph.ts`);
`project` показывает инвалидированные утверждения, а `query` учитывает живость
(`src/ir/project.ts`, `src/tools/index.ts`). `npm run typecheck` чист, `npm test`
проходит (30 тестов). Доки обновлены: `docs/ir_ru.md` §2–4 и
`docs/design_review_ru.md` (R3a).
