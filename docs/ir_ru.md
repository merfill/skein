# Skein — IR: операции, состояние и управление (as-built)

> Английское зеркало — `docs/ir.md`.

Это **as-built**: как IR устроен в текущем коде. Источник истины по семантике —
`docs/ir_semantics_ru.md` (меняется вместе с кодом); справочник операторов —
`docs/ir_operations_ru.md`. Концептуальный обзор — `docs/concepts_ru.md`; модель обхода —
`docs/ir_semantics_ru.md` §2; сквозной пример — `docs/walkthrough_ru.md`.

## 1. Четыре уровня

```
                 append-only              pure            pure
  действия ─▶ журнал (Event[]) ──fold──▶ State ──project──▶ Context ──▶ LLM
     ▲                                                             │
     └─────────── предложение: один или несколько операторов за ход (батч) ◀────────┘
```

1. **Журнал** (`src/ir/events.ts`) — append-only, единственная истина.
2. **State** (`src/ir/graph.ts`) — `fold(events)`: узлы, связи, порядок контейнеров,
   производные хелперы, стек обхода, версии файлов.
3. **Context** (`src/ir/project.ts`) — `project(state)`, детерминированная **лента
   сообщений**.
4. **Лента** — единственная поверхность I/O: системная часть (база + инструкция узла +
   ограничения), запрос с environment brief и история.

Перед `project` движок сверяет активные `ref` с файловой системой (`src/loop/observe.ts`);
замеченный дрейф становится событием `mutate`.

## 2. Узлы и связи

**Узлы** (`src/ir/types.ts`). Рабочее пространство: `request`, `move`, `plan`, `item`,
`action`, `observation`, `stop`, `unactionable`, `constraint`, `fact`. Пространство
артефактов: `file` (а также зарезервированные `symbol`/`test`, не производятся).

- `request.payload = { text }` — сырая мотивация, корень. Проходится как последовательность
  состояний; отклоняется (`unactionable`), если не выполним; ни плана, ни `stop`;
- `move.payload = { state, what }` — объявленное состояние (остров работы) И собственный текст
  цели состояния (`what`; состояние ЕСТЬ его цель, поэтому план висит прямо на `move`); плоский
  ребёнок запроса;
- `plan`/`item` — контейнеры; порядок детей — порядок добавления связей, **последний** ребёнок —
  текущий пункт/альтернатива;
- `action.payload` несёт команду (для правки — `find`/`replace`; для запуска — `signature`),
  чтобы повтор был распознан;
- `observation.payload` чтения несёт `{ ref, version, start, end, total, output? }`; запуска —
  `{ command, exitCode?, output?, outputRef?, error?, errorRef?, signal?, core?, … }` (`output` —
  stdout, `error` — stderr, раздельно; `exitCode` `0` = успех, отсутствует при таймауте); провал
  несёт `failed: true`, неисполнение — `refused: true`;
- `stop.payload = { why? }`, `unactionable.payload = { why? }`, `constraint.payload = { forbid }`;
- `fact.payload = { root, found, missing }` — сессионный факт движка (environment probe),
  записанный один раз на старте запроса; связей нет, проекция рендерит его `user`-брифом,
  подмножество которого зависит от текущего острова.

**Связи** (`src/ir/types.ts`, без поля статуса): `move` (request → move), `unactionable`
(request → unactionable), `plan` (move → plan), `stop` (move → stop), `items` (plan → item),
`alts` (item → action), `result` (action → observation), `mutates` (action → file).

## 3. События (закрытый словарь)

`add_node`, `add_edge`, `descend`, `return`, `mutate`, `record_rejection`. Нет ни `set_status`,
ни `record_check`: смена состояния — новый узел-событие (`move`, `observation`, `mutate`,
`stop`), а не правка. Результат запуска — обычное `observation`; успех/провал читается из его
исхода, а не хранится вердиктом. `record_rejection` используется только для отклонённого
**структурного** хода (`move`/`stop`/`decline`); отказная команда — наблюдение с
причиной.

## 4. Производное состояние (`src/ir/graph.ts`, `src/ir/traversal.ts`)

Узлы не меняются; `fold` вычисляет факты, а читает их `graph.ts`:

- **`actionExecuted`** — у действия есть произведённый ребёнок (`result`/`mutates`);
- **`actionSucceeded`** — оно изменило файл, либо его наблюдение-результат не провал (`failed`
  или ненулевой `exitCode`; отсутствие `exitCode` — таймаут);
- **`hasStopped`/`stopOf`** — связь `stop` (на `move`); **`unactionableOf`**; **`currentMove`** —
  последний ребёнок `move` запроса; **`isMoveFinished`** — остановленный `move` (включая
  терминал);
- **`lastChild`** — текущий пункт/альтернатива; **`itemFulfilled`** — его текущая альтернатива
  исполненное успешное действие (только действия); **`cursorOf`** — первый невыполненный пункт;
  стек — свёртка `descend`/`return`.

**Предикатов истины на узлах нет.** Код возврата запуска — факт, который читает модель;
состояние закрывается только `stop` доксы.

## 5. Операторы доксы

`src/llm/schemas.ts`, `src/tools/index.ts`, врата `src/loop/classify.ts`:

- **`move`** `{ state, what }` — объявляет состояние, в котором работать (переход
  автомата), И собственный текст цели состояния (`what`; обязателен, кроме терминального
  состояния); состояние ЕСТЬ его цель, поэтому план висит прямо на `move`, и первый `apply`
  его засевает. Допустим на свежем запросе или на завершённом состоянии; состояния — плоские
  дети запроса.
- **`apply`** `{ action }` — команда исполняется; размещение по исходу текущего пункта
  (`OP-AP-PLACE`): успех → новый пункт плана, иначе → новая альтернатива; неисполнение
  (повтор/stale/запрет/пусто) — наблюдение с причиной.
- **`stop`** `{ why? }` — узел `stop`, подвешенный к `move` фокусного состояния связью
  `stop` (на терминальном состоянии завершает запрос); у запроса `stop` нет.
- **`decline`** `{ why? }` — узел `unactionable` под запросом; только на свежем запросе.
- **`recall` / `search`** — read-only адресация сохранённого тела результата (окно / паттерн).

Врата в `classify` обслуживают только структурные ходы (`state_open`, `no_state`,
`empty_state`, `not_addressed`, `not_request`, `interpreted`, пустые поля); стражи
команд (`repeated_action`, `stale_base`, `constraint_violation`, пустая команда) живут в движке и
дают наблюдения (`src/tools/index.ts`).

## 6. Обход (логос)

`src/ir/traversal.ts`: `focusEvents` спускается из запроса в текущий `move`
и возвращается из завершённого состояния. `applicable` даёт доксе допустимые ходы
(`move`/`apply`/`stop`/`decline`) из тех же фактов, что и врата; `src/loop/propose.ts` связывает
из него предложенную поверхность инструментов (`toolNamesFor` → `allowedTools`), поэтому
отклоняемый ход не предлагается. Цикл
(`src/loop/graph.ts`): `project → propose → classify → execute → progress`; прогон
заканчивается, когда остановлено терминальное состояние (`request_addressed`), либо по
`no_progress` / бюджету (`maxTurns`).

## 7. Проекция

`Context` (`src/ir/project.ts`) — `{ history, situation, applicable, constraints, … }`: лента ходов
`user`/`assistant`/`tool` (собирается из дерева), текущая ситуация
(`request`/`plan`/`working`/`transition`/`terminal`), допустимые ходы и ограничения. `src/loop/propose.ts` собирает
сообщения для модели: базовый промпт, ограничения, историю и — в конце (временно) — инструкцию
текущей ситуации. Состояние — это решение, а не вызов инструмента: оно рендерится маркером
`Start state <label>` (ход `assistant`), инструкцией состояния (ход `system`) и целью состояния
ходом `user` (`what: <цель острова>`); завершённое состояние сворачивается в `Start state <label>`
/ инструкция / цель / `Finish state <label> — <why>` (причина `stop`, из связи `move.stop`) — ходы
плана уходят из ленты. Запрос — второе сообщение ленты (сразу после базового промпта), на каждом
ходу. `tool`-сообщения
несут ограниченное inline-тело (голова инспекции, хвост команды, когда оно большое); полное тело
адресуется по id через `recall`/`search`. Отклонённый `classify` структурный ход узла не создаёт,
поэтому его причина приходит транзиентным `tool`-сообщением на следующий ход. Полная
спецификация — `docs/projection_ru.md`.

## 8. Честность и границы

- состояние закрывается **только `stop`**; движок никогда не помечает состояние «achieved»;
- запрос в IR не закрывается: приёмка внешняя; прогон заканчивается, когда остановлено
  терминальное состояние или при `decline`;
- отложено: переинтерпретация запроса, отрицательный/сдающийся `stop`, `out_of_fragment`,
  точность свидетеля (весь воркспейс, `SKIP_DIRS`), `symbol`/`test` и составной системный промпт
  (граница базы/узла — следующий этап).
