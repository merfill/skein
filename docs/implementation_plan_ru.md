# Skein — общий план реализации

> Русское зеркало `docs/implementation_plan.md`.

Концепция — `docs/concepts_ru.md`. Концептуальный каркас — докса/логос в
`ankyra/docs/doxa_and_logos.tex` и `ankyra/docs/concepts_ru.md`. Детальный спек
текущего этапа — `docs/tier0_plan_ru.md`. Этот документ — общий план, решения,
роадмап и статус.

## 1. Суть

Skein — агент кодирования, у которого контекст есть **проекция IR**, а не лента
сообщений. LLM — докса: только предлагает (`status=open`). Детерминированный
движок и свидетель — логос: решают. Журнал событий и функция проекции — протокол.

## 2. Зафиксированные решения

| Решение | Выбор |
|---|---|
| Язык | TypeScript (Node 22, ESM), пакетный менеджер npm |
| Модель состояния | гибридный граф `work` + `artifact`, append-only журнал + детерминированная проекция |
| Немонотонность кода | staleness по версии (хэш файла), без ручного отката |
| Первый срез | багфикс по падающему тесту; свидетель — test runner |
| Оркестрация | LangGraph.js (`@langchain/langgraph`) |
| LLM | как в Ankyra: OpenAI-совместимый endpoint, **размышления выключены** (`thinking.type=disabled`, `reasoning.effort=none`); секреты — только в `.env` |
| Свидетель | объективный (test runner) + субъективный (пользователь/приёмка) |

## 3. Роадмап

**Tier 0 — багфикс по падающему тесту (выполнен).**
Замкнутый цикл `goal → locate → claim → action → check → done`; IR + проекция;
staleness; объективный свидетель. Детали — `docs/tier0_plan_ru.md`.

**Tier 1 — работа над задачей.**
- `Decision` как first-class: выбор, отвергнутые альтернативы, обоснование.
- `Check`/свидетель как явный узел с объективным вердиктом.
- Подцели и их декомпозиция.

**Tier 2 — немонотонность знания.**
- Статусы `superseded`/`refuted`, специфичность, `Revision` как запись.

**Tier 3 — доксические операторы.**
- `analogy`, `intuition` — запрос у LLM невыводимого, как явные операторы.

**Ближайшие шаги.**
1. Ужесточить классификацию: constraint должен запрещать обход через `run`
   (shell), а не только через `edit`.
2. Задачи на длинный горизонт, где проекция должна дать преимущество
   (многофайловые правки, 50+ шагов).
3. Сравнение Skein vs opencode vs монотонный агент на одних задачах.

## 4. Текущий статус

Реализован Tier 0 (шаги 1–5 `docs/tier0_plan_ru.md` §11): `src/ir`, `src/config`,
`src/llm`, `src/tools`, `src/loop`, три фикстуры, offline- и live-гейт. Полный
статус и осознанные упрощения — `docs/tier0_plan_ru.md` §13.

Проверка: `npm run typecheck`; `npm test` — offline-тесты, live-гейт только при
`SKEIN_LIVE=true`.

## 5. Границы

Сознательно не входит в текущие этапы: AST/символьная таблица, эмбеддинги,
CSP/арифметика, UI, мультиязычность, несколько LLM-провайдеров.

## 6. Открытые вопросы

- Обход constraint через `run` (см. ближайшие шаги).
- Валидация предложений: жёсткий zod-контракт vs мягкий fallback JSON (как в
  `llm/structured.py` Ankyra).
- Формат `payload` для `finish`/`run`: свободный текст vs типизированный предикат.
- Кэш: стабилен только header (goal + constraints), frontier меняется каждую волну.
