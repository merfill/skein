# Skein — инструменты и контракт вызова

> Английское зеркало — `docs/en/tools.md`.
>
> Это контракт для модели: что она может вызвать, что возвращает каждый инструмент и как отказы
> попадают на ленту. Семантика IR — в `ir_operations.md`; поверхности инструментов по
> состояниям — в `states.md`; лента — в `projection.md`.

## 1. Поверхность модели

Модель отвечает нативными вызовами инструментов. Исполнитель переводит каждый вызов в действие
IR; модель никогда не работает с id узлов IR напрямую.

- `move` объявляет следующее состояние.
- Рабочие инструменты — `read`, `grep`, `list`, `edit`, `write`, `bash`, `webfetch`,
  `apply_patch` — являются действиями IR `apply`.
- `recall` и `search` читают сохранённый результат по id.
- `decline` отклоняет запрос, у которого нет действенной задачи.

Инструмента **`stop` нет**. Состояние закрывается обычным текстовым ответом; исполнитель
записывает его как `stop`. `move` и `decline` — единственные структурные инструменты: они меняют
машину состояний, а не рабочую область.

Имена, параметры и описания инструментов уходят полем `tools` запроса, которое генерируется из
`PROPOSAL_TOOLS` (`src/llm/tools.ts`). В тексте промпта они не повторяются.

## 2. Инструменты

| Инструмент | Параметры | Что делает | Что возвращает |
|---|---|---|---|
| `move` | `{ state, what? }` | объявляет следующее состояние; `what` — необязательная заметка о предмете | лента показывает `Start state <label>`; первый `apply` засевает ходы состояния |
| `read` | `{ filePath, offset?, limit? }` | читает файл или окно строк (`offset` — первая строка с 1, `limit` — максимум строк) | не более ~8K символов сверху (или с `offset`); для большего окна — `[lines X-Y of Z; continue from Y+1]` |
| `grep` | `{ pattern, path?, include?, from? }` | ищет по содержимому файлов регулярным выражением; `path`/`include` задают область | простой текст с номерами строк (`path:line:match`, контекст `path-line-text`, по умолчанию 3/3); `from` — начало с 1, по умолчанию 50 и максимум 100 совпадений |
| `list` | `{ path?, include?, from? }` | перечисляет файлы рабочей области; `path`/`include` задают область | JSON; по умолчанию 100 файлов, максимум 200; окно держится около 8K |
| `edit` | `{ filePath, oldString, newString }` | заменяет первое вхождение `oldString` в существующем файле | меняет файл; лента показывает `mutated <path>` |
| `write` | `{ filePath, content }` | создаёт новый файл или полностью перезаписывает существующий | меняет файл; для перезаписи нужно свежее чтение файла |
| `bash` | `{ command, workdir?, timeout? }` | выполняет одну синхронную команду из корня рабочей области; `workdir` выбирает подкаталог; `timeout` — в миллисекундах | `exitCode` и вывод; stdout и stderr захватываются раздельно; показывается хвост (~8K), полный поток сохраняется |
| `webfetch` | `{ url, path? }` | загружает URL в рабочую область или в служебный путь, если `path` не задан | файл только для чтения; в IR записывается как `fetch` |
| `apply_patch` | `{ patch, strip? }` | применяет unified diff (`patch -p<strip>`, по умолчанию 1) | меняет затронутые файлы |
| `recall` | `{ id, start?, end? }` | читает сохранённый результат по id, при необходимости окно строк | тело или окно с курсором `continue from N` для длинного тела |
| `search` | `{ id, pattern, before?, after? }` | ищет внутри сохранённого результата по id регулярным выражением; ищет по stdout и stderr | окна совпавших строк простым текстом, с контекстом (по умолчанию 3/3) |
| `decline` | `{ why? }` | отклоняет запрос, намерение которого недейственно | записывает `unactionable` и завершает запуск; доступен только пока у запроса нет состояния |

`edit` отказывает, если `oldString` отсутствует, файл изменился после чтения (`stale_base`),
ограничение запрещает путь или файла нет. `write` отказывает для нечитанного файла или
устаревшей базы. `bash` отказывает при идентичном повторе против неизменного мира; таймаут не
несёт кода возврата. `grep`, `list` и `read` также отказывают при идентичном повторе против
неизменного мира. Голый `recall` уже видимого тела отклоняется; оконный `recall` — новое
содержимое. У `search` нет постраничности: широкий шаблон ограничивается с пометкой сузить его.

## 3. Контракт результата

Тело любого результата инструмента ограничено одним встроенным бюджетом — 8K. Лента показывает
окно инструмента целиком и никогда не вырезает его середину:

- результат инспекции (`read`, `grep`, `list`, `recall`, `search`) сохраняет голову до 8K; большее
  тело листается;
- вывод команды (`bash`) сохраняет хвост до 8K.

Ограничивается только тело, всё ещё превышающее бюджет, с пометкой об опущении.

Исполнитель сохраняет полное тело файлом, а действие хранит `outputRef`. Доступ — по
идентификатору, не по пути: `recall { id, start?, end? }` читает фрагмент, `search { id, pattern }`
ищет по телу. `recall` или `search` — сам по себе ход открытого состояния и уходит с ним при
закрытии.

`edit`, `write` и `apply_patch` меняют файлы и дают на ленте `mutated <path>` вместо тела
наблюдения. Проваленный вызов никогда не выбрасывается: он записывается как наблюдение с
причиной.

## 4. Отказы

**Структурный** ход (`move`, `decline`) отклоняется исполнителем, если он недопустим: узел не
создаётся, а причина приходит на ленту разовым `rejected <move>: <reason>` на следующем ходу.

**Команда** не отклоняется как структурный ход. Её неисполнение записывается как действие и
наблюдение с причиной: `repeated_action`, `stale_base`, запрещённый путь, пустой `bash` или путь
вне рабочей области. Провал инструмента — провальное наблюдение: отсутствующий файл, недопустимая
область `grep`/`list`, отсутствующий `oldString`, ненулевой код возврата, таймаут или сигнал.

Точные токены причин и id реестра — в `ir_operations.md` §5.

## 5. Поверхность инструментов по состояниям

Исполнитель связывает предложенные инструменты из `Context.applicable`, который выводится из
`Island.applies`:

- свежий запрос предлагает `move` и `decline`;
- переход предлагает `move`;
- открытое состояние предлагает инструменты действия состояния плюс `recall` и `search`;
- терминальное состояние не предлагает ничего, потому что модель закрывает его текстом.

Наборы инструментов по состояниям перечислены в `states.md`. `bash` двойного назначения, но
инструкция состояния всё равно ограничивает работу: Verification не должна менять артефакт, а у
End инструментов нет.

## 6. Зачем так

- **Честные лимиты.** Каждый инструмент объявляет бюджет и сообщает курсор продолжения вместо
  молчаливого среза результата.
- **Адресуемые результаты.** Большое тело остаётся в журнале и достаётся по id, а не копируется
  в контекст заново.
- **Один плоский инструмент на операцию.** Модель вызывает нативный инструмент; исполнитель
  переводит его в действие IR. Имена на поверхности близки к приорам кодирующей модели.
- **Отдельного `stop` нет.** Закрытие — текстовый ответ, который записывает исполнитель; нет
  инструмента, единственная задача которого — закрыть состояние.

Не-цели: никаких инструментов фоновых задач на поверхности модели, никаких селекторов дерева,
никаких VCS-инструментов и никакого скрытого бюджета контекста, который обрезает результат
инструмента.
