# Skein — план: завершение, дистрибутив, оценка, публикации

> Рабочий документ, RU-only (как `handoff.md`). Здесь план работ, а не текущее состояние:
> состояние — в `handoff.md`. Порядок фаз: A → B → C → D. Фазы B и C частично параллельны.

## 0. Цель и рамка

Цель — не продукт с метриками adoption, а **исследовательский артефакт и публичная работа**:

1. довести Skein до честного v0.1;
2. выпустить воспроизводимый дистрибутив (исходники, npm, Docker);
3. провести сравнительную оценку с opencode на 13 задачах, K=5;
4. опубликовать подробный технический отчёт на Zenodo и популярную статью на Хабре.

**«Бесплатный доступ»** здесь означает: открытый исходник + BYOK + локальные модели +
документированные free-tier провайдеры. Свой хостинг-шлюз с бесплатными ключами **не делаем**
(расходы, абьюз, ToS, юридические риски). Пользователь платит своему провайдеру или запускает
Ollama локально.

**«Готово» для v0.1** = артефакт + воспроизводимый прогон + отчёт. Не «все фичи плана».

## 4. Фаза C — сравнительная оценка (13 задач, K=5) — **сделано (2026-11-13)**

Кампания завершена: 250 runnable клеток, **246 solved** (Skein/on 63/65, Skein/off 60/60,
opencode/on 65/65, opencode/off 58/60). Разбор токенов/стоимости и состояний —
`bench/results/campaign-k5/`. Осталось только перенести это в отчёт (Фаза D).

### 4.1. Задачи

13 ported terminal-bench задач из `tests/sandbox/tasks/registry.ts` (кэш задач —
`~/.cache/harbor/tasks/<hash>/<id>/`):

`regex-log`, `fix-git`, `log-summary-date-ranges`, `openssl-selfsigned-cert`,
`git-leak-recovery`, `cobol-modernization`, `modernize-scientific-stack`,
`custom-memory-heap-crash`, `password-recovery`, `db-wal-recovery`, `crack-7z-hash`,
`fix-code-vulnerability`, `fix-ocaml-gc`.

### 4.2. Дизайн

- **Агенты:** `skein`, `opencode`.
- **Сеть:** `on` (весь набор) и `off` (12 задач; `crack-7z-hash` требует сеть — `unsupported`).
- **Повторы:** K=5.
- **Паритет модели:** один провайдер и модель, одинаковый reasoning (`low`).
- **Паритет бюджета:** Skein `--turns` = `task.maxTurns` (60 для `fix-ocaml-gc`, иначе 80);
  opencode `--max-steps` = тот же бюджет (steps ≈ turns: один LLM-вызов на шаг).
- **Без wall-clock таймаута** (протокол владельца): не передавать `--timeout`; opencode при
  `--seconds 0` не ограничен по времени.

### 4.3. Прогон

Сначала **разминка**: live-валидация маршрутизации (`plan` / `revision` / `write_document`,
многоходовый REPL) — чтобы в кампанию не пошёл сломанный роутинг.

Потом **пилот**: по одному прогону на задачу (2 агента), замерить время и стоимость,
экстраполировать ×5 и зафиксировать бюджет. Только потом — кампания.

Кампания — `tests/sandbox/campaign.ts` (одна задача за раз; `--concurrency` — общий лимит
клеток; `--task-concurrency` — per-task, для `fix-ocaml-gc`). Фактический запуск:

```sh
SKEIN_LIVE=true npx tsx tests/sandbox/campaign.ts --repeat 5 --concurrency 10 \
  --task-concurrency fix-ocaml-gc=3 --out bench/runs/matrix/campaign-k5 --resume
```

Для одной задачи можно вызвать `matrix.ts` напрямую (см. `docs/en/testing.md` §4.1).

Правила батча (из `AGENTS.md`): клетки параллельно, кап по ходам, без wall-clock таймаута,
никаких последовательных shell-циклов по клеткам (`--resume` вместо перезапуска).

### 4.4. Метрики

На клетку: `reward`, `turns`/`steps`, `inputTokens`, `freshInput`, `cacheRead`,
`outputTokens`, `reasoningTokens`, `costRub` (только Skein), `elapsedMs`, `status`
(`ok`/`reward0`/`error`/`timeout`/`unsupported`).

В отчёте: solved/всего, медиана и разброс, распределение по задачам; **все** клетки, включая
провалы и ошибки. Не выбрасывать неудачные прогоны и не отбирать лучшие.

### 4.5. Честность и ограничения

- Протокол (задачи, K, сети, модель, капы, бюджет) фиксируется **до** кампании.
- Confounders: у opencode нет `costRub`; разные определения шага/хода; кэш промпта влияет на
  `inputTokens` (поэтому отдельно `freshInput`); wall-clock у opencode vs бюджет ходов у Skein.
- Один провайдер/модель — это ограничение, а не «SOTA-заявление».
- Сырые артефакты (`manifest.json`, `summary.json`, `cells/**`, трассы) публикуются.

### 4.6. Артефакты

`bench/runs/matrix/campaign-k5/` (сырые клетки) + `bench/results/campaign-k5/` (сводки и
разборы: `summary.*`, `token-comparison.*`, `state-cost.md`, `manifest.json`). В отчёт —
таблицы по задачам, стоимости и состояниям; графики при желании.

## 5. Фаза D — тексты

### 5.1. Zenodo: подробный технический отчёт

Формат — preprint / technical report (Zenodo не рецензирует; так и писать). Структура:

1. Motivation: контекст как детерминированная проекция монотонного журнала, а не transcript.
2. Related work: agent frameworks, context management, SWE-агенты, neuro-symbolic reasoning.
3. Архитектура: журнал/IR, предикаты проекции, executor, состояния/переходы, session units, plan.
4. Реализация: провайдеры (OpenAI-compatible/BYOK), инструменты, TUI, sandbox, телеметрия.
5. Evaluation: протокол §4, baselines, метрики, ablations (projection vs transcript,
   request-as-reference, plan vs без плана), стоимость.
6. **Состояния vs субагенты** (см. 5.2).
7. Limitations / threats to validity.
8. Reproducibility: Docker, команды, конфиги, бюджет прогонов.
9. Conclusion / future work.
10. Appendix: промпты, схемы, примеры трасс, таблицы по задачам.

### 5.2. Раздел «состояния vs субагенты»

Тезис: и состояния, и субагенты декомпозируют работу и изолируют контекст, но устроены
по-разному.

| | Состояние (Skein) | Субагент |
|---|---|---|
| Контекст | проекция общего монотонного журнала | отдельная лента сообщений |
| Цель | явные `what` + `Done when` + surface | промпт делегирования |
| Исполнитель | один model, executor записывает | отдельный вызов/цикл модели |
| Наблюдаемость | `recall`/`search`, общий журнал | только возвращённый результат |
| Стоимость | без второй модели, но общий контекст растёт | изоляция контекста, но дублирование |
| Параллелизм | последовательные переходы | естественный fork/join |
| Закрытие | текст модели (`stop`), критерий — якорь, не гейт | возврат результата родителю |

Research questions: снижают ли явные состояния дрейф и токены по сравнению с субагентом?
Когда изоляция субагента выгоднее (контекст/параллелизм)? Гибрид: состояние как форк журнала
с явным join. Ограничение Skein: критерий не проверяется движком, premature stop возможен.

### 5.3. Хабр: популярная статья

Нарратив, не отчёт: «зачем агенту журнал вместо ленты», 2–3 живых примера, реальные цифры и
цена, ссылка на артефакт и DOI. Публиковать **после** релиза и отчёта, чтобы ссылки не вели
в пустоту. Анонсы — после Нового года.

## 6. Риски и развилки

- **Бюджет/время C:** 13×2 агента×2 сети×5 — дорого по времени и Docker. Пилот + бюджетный
  гейт обязателен; при нехватке — приоритет `net=on` (все 13), затем `off`.
- **Паритет с opencode:** версия, модель, reasoning, капы. Зафиксировать в отчёте.
- **Zenodo без рецензии:** не называть SOTA; формулировать как воспроизводимый отчёт.
  Позже — submission в workshop (не блокирует v0.1).
- **Free access:** только BYOK/локально/free-tier; хостинг-гейтвей не делать.
- **Безопасность:** агент исполняет shell; документировать sandbox/подтверждения, хранение
  ключей (0600), отсутствие телеметрии.
- **Два проекта:** Ankyra (рассуждения/верификация) и Skein (контекст/оркестрация) —
  связывать в один research narrative, не смешивать кодовые базы.
